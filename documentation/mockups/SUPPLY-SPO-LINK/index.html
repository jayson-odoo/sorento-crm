Why option (b): after the fix, a PO line that already moved onto an SPO leaves the Supply tab (its SPO row, or the bin's on hand once landed, shows instead). On the dev copy only 2 open PO lines are part-moved onto an SPO, so in option (a) the column reads "-" on almost every row. Option (b) also links each SPO row back to its PO, the way the SPO document's own Lines tab shows "PO (book)".

The reported product after the fix (dev copy, SRTSS4210, Oct 26 cell): Supply (1,008) = On hand BRW 32 + On hand BRW-BB 976, and BRW-BB is assigned to SO364824 line 880 (486) and SO364922 line 464 (490), the lines the two placements were made for. The two "PO 202607-S0100" rows are gone. The Dec 26 lines (1040 and 624, 976 in all) now read short, because those units were already promised.

What each element reuses (no new component)

  • Popup shell, tabs, Supply grid, Total footer: app/(protected)/project-sales/stock-debt/components/StockDebtCellDialog.tsx (PanelDataGrid, components/common/PanelDataGrid).
  • SPO number link and its popup: OrderInquiryDocumentLink kind="spo" (app/(protected)/project-sales/order-inquiries/components/OrderInquiryDocumentDialog.tsx), the link the Document cell already uses for an SPO row.
  • PO number link in option (b): OrderInquiryDocumentLink kind="po", the link the Document cell already uses for a PO row (via PoLineLink, lib/stockDebtDemandColumns.tsx).
  • Column sizing and truncation: fixed table layout, explicit size, truncate + title, same as the neighbouring columns.
  • Data: SPO lines matched to the PO line by the order inquiry page's own key (PO number + PO line ref + product), one read per popup.
