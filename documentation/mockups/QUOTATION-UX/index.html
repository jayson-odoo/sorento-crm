?Behaviour card: the rules this mock proposes, and five decisions for the owner

Owner decisions, 14 Oct

Q1 (a) a product with exactly one "Product Photos" image uses it, everywhere; several: the user chooses (section 2b). Q2 (a) drawings on the grid, the PDF and the Excel, frozen at issue in a new drawing_attachment_id column; several: the user chooses, same picker. Q3 "Custom item". Q4 (a) "Priced per" in Line details. Q5 (a) "Stock at" dropdown, remembered per browser, reusing the Fulfilment Planning / Order Inquiry stock components. Section 3 (stock popover): owner "ok".

Rules

R1 The quotation line table is the app DataGrid: drag rows by the handle, resize and reorder columns, layout remembered per user. A section bar drags with the line it opens. Line numbers stay continuous through sections (today's rule, QuotationVersionEditor.tsx:353-364).

R2 At 1280 px with the sidebar open, a row never scrolls sideways (grid 910 px). Photo and Drawing are 40 px thumbnails opening the existing viewer.

R3 Drawing = the product's attachments of type Technical Specifications that are images (dev: 1,180 products have one, 1,124 exactly one, 56 several, max 6). A custom item, or a product without one, shows "no drawing".

R4 Brand is picked from the brands master (stored as the brand name, as today: brand_snapshot). Picking a product still fills brand, description, UOM and list price (:304-328).

R5 Description is multi-line; line breaks are kept on screen, PDF and Excel.

R6 Stock chip = Available (on hand - SO qty + SPO qty, project_fulfilment_board_service.py:1240-1244) for the chosen group, popover adds site pools and incoming SPOs: the same stock-detail endpoint and table Order Inquiry uses. Read-only; never blocks Save. No chip on a custom item.

R7 Wording: "Off-catalog" becomes "Custom item"; "Counts per" becomes "Priced per" inside Line details (it changes no total, section 8). Rate only stays one click, under the total.

Unchanged: totals (rate-only excluded), one Save for every scope, below-floor / non-standard checks, revisions, item numbering.

Edge cases

Product with 2+ drawings (SRTWB1410: 2, SRTWB1421-RW: 6): count on the thumbnail, viewer pages through them. Product with no photo chosen (dev: 1 of 2,308 products with photos has one chosen): today's "No photo chosen" link stays, see Q1. Negative Available (SRT6641 BB -37): red chip, number shown as is, never clamped (stock-detail rule). Search hides rows but keeps numbering and totals (today). Frozen / issued version: read view only (today).

The five questions as asked (answered above)

Q1 Photo when nobody has chosen one. Photo shows only the chosen photo (product_image_service.py:117-137, "no fallback" by design), and in dev 2,060 of 2,308 products with photos have exactly ONE "Product Photos" image but only 1 product has a chosen one, so almost every line shows "No photo chosen". (a) Recommended: use the photo when the product has exactly one "Product Photos" image; still "No photo chosen" when there are several. Applied in product_image_service.py, the one photo decision the brochure, 3D models and quotation all read, so they never disagree. (b) keep chosen-only; someone picks photos in Products first.

Q2 Which drawing, and does the print change? PDF and Excel print the typed tech-spec TEXT today (project_quotation_pdf_service.py:396, project_quotation_excel_service.py:433-434). (a) Recommended: thumbnail = the product's first drawing by upload order, viewer shows all; PDF and Excel print that drawing in TECHNICAL SPEC like your Excel; the typed tech-spec box leaves the grid (old text kept and printed under the description). Needs one new column on quotation lines so an issued quotation keeps the drawing the customer got, frozen at issue exactly like the photo (project_quotation_image_service.py:1-17). (b) screen only, print unchanged. (c) add a "chosen drawing" on the product like the photo (schema change, bigger lane).

Q3 Name for a line with no product. (a) Recommended: "Custom item". (b) "Not in catalogue". (c) other wording.

Q4 "Counts per". It is stored and validated but changes no total and is not printed (section 8). (a) Recommended: move into Line details as "Priced per", reference only. (b) remove from the screen (data kept). (c) make it multiply qty by the project's unit / bathroom counts (new feature, separate lane).

Q5 Whose stock locations? Nothing links a user to locations today: no user-warehouse link, 3 of 74 users reach a sales agent through their portal contact and none of those agents has a location group (dev query); "own" on the board is the SO's warehouse and the sales agent's location_group (project_so_draft_service.py:3238-3273). (a) Recommended: a "Stock at" group dropdown on the Lines tab (BB / NTC / IB / IR / AM, the fulfilment-planning groups), remembered per browser; no schema change. (b) a stock group set per user in User Management (schema change, bigger lane). (c) read it through user → portal contact → sales agent (no data today).

8What the two confusing labels actually do today (read from the code)

"Off-catalog" = the line has no product picked

Nothing else. product_id is empty, so: the badge shows (QuotationVersionEditor.tsx:1055-1058, read off the live draft); the description becomes required, on screen (:119-123) and on the server (project_quotation_service.py:649-657, 422 "An off-catalog line needs a description"); the line is always flagged Non-standard (:522-529); there is no photo, list price or price floor to compare against (product_image_service.py:141-143). It prints like any other line.

Today
Product picker placeholder "Off-catalog line" · badge "Off-catalog" · error "Needed on an off-catalog line"
Proposed
Placeholder "Pick a product" · badge "Custom item" · error "A custom item needs a description" · recompute note "… stays a custom item"

"Counts per" (unit_type) = a label only; it changes no number and is not printed

Four choices: Per house unit / Per bathroom / Per facility / Common area (QuotationVersionEditor.tsx:55-60; backend models/projects.py:787-799). It is stored (projects.py:1441), checked against the four values (project_quotation_service.py:603-608), copied into a revision (:350) and sent back to the screen (:1214). The line total is always qty × unit price (:659-661); the PDF and Excel exports never read it (no reference in project_quotation_pdf_service.py or project_quotation_excel_service.py). "Not counted per unit" is just the empty choice's placeholder, 168 px wide, which is why it wraps.

Today
Column "Counts per", placeholder "Not counted per unit", in every row
Proposed
In Line details: "Priced per" · Each house unit / Each bathroom / Each facility / Whole site (common area) · empty = not set · hint "For your reference only. Does not change the total."
