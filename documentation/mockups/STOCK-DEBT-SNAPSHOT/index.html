11Shared pieces: two perspectives, one component, one queue

Nothing about requesting or sending is built twice. The OI page keeps behaving exactly as today; it just imports the shared files instead of holding them. The snapshot only adds where it opens them from.

OI perspective (today, #1684)
  • OI page, Lines tab: tick rows → Actions > Request CS to reserve
  • Order inquiries list: Reserve filter + column
  • Order inquiries list: Actions > Send all parked requests to CS (N)
Shared (one copy each)
  • _shared/components/RequestReserveDialog.tsx: rows, Requested, Location, Note, Park this first, Send / Park
  • _shared/lib/reserveEligibility.ts: which rows can be requested, remaining
  • _shared/hooks/useParkedSendActions.tsx: the two Actions items with N, opening components/common/ParkedSendDialog.tsx
  • Backend, unchanged: reserve-requests POST (with park), parked preview / send, park_send.py, the one parked queue (order_inquiry_reserve_requests.parked_at)
Stock Debt perspective (new)
  • Snapshot drill: per OI group → Request CS to reserve (this product's requestable rows, decision's pool as default)
  • Snapshot page: Actions > Send all parked requests to CS (N)
  • Now column: the request's state, wherever it was made

The snapshot drill loads the OI's live rows with the OI page's own query (useOrderInquiryHeaderLines) when the dialog opens, so the dialog is fed the same rows the OI page feeds it. Moving the files is the only change to the OI side; its existing tests move with them and must stay green.
