Annotation 2 (line format). Every figure line is Qty n, RM x, the top selling ranking's own row format (presenters.py::_top_selling_row: CODE: Qty q, RM v), so the two reports read the same. Annotation 3. Header labels, Total and section titles are bold.

Annotation 4 (channel and location). No Channel line here: Jayson's six accounts are all retail, so the channel is fixed to retail in code and there is nothing to choose. Source: each linked account's customers.market_segment_code, read through app/services/scm/demand_class.py::class_of (a segment named project or contract is the project channel, every other segment is retail, the same rule the SO import uses to class demand). Annotation 7 (period granularity). The parser gives only the window; the grouping is decided in code from the window: one day prints that date, up to 7 days prints by day, up to a calendar month prints by week (Monday to Sunday, clipped to the window), longer prints by month, latest first. Only buckets with a delivery print.

v2 annotation 1 (numbering). Numbers never repeat inside one message: the list rows take 1 to N, the drill options continue at N+1. The route numbers both, so what is printed, what is stored as the open question and what a reply resolves against are one list.

Annotation 8 (single dimension). Every drill is one dimension over the SAME full scope (the six accounts, the same window): By customer, By product, or the delivery order list. The rows of a drill are not picks and nothing nests; after a drill the two other views are offered, so the reader can hop between the three without going back. Accounts with nothing delivered in the window are not listed (A/C II, the plain account, CERAMIC & ELLECI). Rows are ranked by amount; the delivery order list is latest first and names the account when the scope holds more than one; a list longer than 10 rows prints the top 10 and a line "and N more". The DO number, ranks and figures are the route's own; the reply only prints them.

Annotation 6 (typed words). "by product", "by customer", "DO", "delivery order", "delivery orders" all pick the same option as its number. Two existing mechanisms carry it: the option's own label typed back matches exactly (turn/decide.py::_positions_by_label), and a paraphrase ("the DO list", "show per product") arrives as the parser's reference_positions against the printed roster (turn/decide.py::picked_positions). Short aliases the label match cannot cover ("DO", "delivery order") are added to the option itself, so the match stays a label match and never a word list in the engine.

Answer to annotation 5 (v2 annotation 3: no new logic). Nothing is designed here: this is the engine's existing open-question rule, reused exactly. A message that names its own subject or another domain is a NEW ASK (turn/decide.py, rows entity_op_replace, domain_in_message, names_its_own_entity), answered normally, and turn/apply.py::_answer_outstanding drops the open offer on it (trace rule outstanding_pending_dropped; pinned today by test_sales_report_lane.py::test_a_business_query_with_a_domain_hint_is_a_new_ask_and_drops_the_offer). A casual aside keeps the offer open silently (test_offer_survives_a_casual_turn); a message the bot cannot read re-prints it once and a second one closes it (test_an_unreadable_turn_reprints_once_then_the_second_closes_it). The drill-down roster is a sales_report_detail open question, the same kind the SO list offer used, so every one of those rules applies to it unchanged. The "2" typed after the stock answer lands on no open question and gets the usual clarifier.

An out-of-range number re-asks with the same options (the existing re-ask path, lanes/business/__init__.py::_outstanding_detail_reoffer). A casual aside carries the open options silently (the standing rule for every open question), so "1" still works on the next message.

Answers to the two questions left open in v1

Third option. Kept as the delivery order list ("Delivery orders", also reachable by typing "DO" or "delivery order", annotation 6). It is the last rung: nothing below it to drill into, and after it the two other dimensions are offered again.

Nested drilling. Withdrawn per annotation 8: no drilling inside a drill. The three views (By customer, By product, Delivery orders) always run over the full scope of the original ask, and each reply offers the other two.

Header lines and money format are the presenter's own (RM with thousands separators, dates dd/mm/yyyy, months "Sep 2026", latest first). Every number on a screen is a reply option once, never two lists with overlapping numbers. Rows inside a drill are numbered for reading only; the reply options are the ones under "Drill down:".
