5No autosave exists; what the complaint actually hit

Every server draft write goes through one route, reached only by a click. Nothing saves on a timer, on blur, on navigation or on board load.

Writers (all explicit): PUT /fulfilment-planning/lines/{key}/draft (app/api/v1/projects/fulfilment_planning.py:393 -> project_line_draft_service.save_draft) is the only backend path that inserts a draft row. It is called from FulfilmentBoardPanel.tsx:854 (decide()), which fires only from: the row editor's "Save decision" button (BoardLineDecisionPanel.tsx:604), the verdict chips, the Decide strip (BoardDecideControl.tsx, one PUT per ticked row), the cell dialog's bulk verbs, and the header's "Save all suggested" (FulfilmentBoardPanel.tsx:1990).
Not writers: planning-change pre-marks are local only (FulfilmentBoardPanel.tsx:684, preMarked: true, never PUT and never posted, S5); the board-read seeding effect (FulfilmentBoardPanel.tsx:738) copies drafts the server already holds into the screen, it writes nothing; the undo reconstruct never writes a draft (project_supply_undo_reconstruct_service.py:631); the board read commits only a mirror line, never a draft.
What SO402757 hit: an explicit Approved save by Jayson Foundryx on line 8 (22 Sep 03:09 UTC) that revision 1, three minutes later, did not name, so it stayed on the server. Saved drafts are shared and persistent by design (R-F: "a second planner sees the first planner's saved lines", project_line_draft_service.py:233 upsert keyed by core line), and Confirm posts every saved draft on the board (FulfilmentBoardPanel.tsx:1319). That persistence, not an autosave, is what rode along with Cyndi's press. The Preview above makes it visible and untickable before anything is sent.
Owner call: keep explicit saves only (nothing to remove). Optionally, drafts saved by another planner could require re-saving before they are sent; say so on the mock if wanted.
