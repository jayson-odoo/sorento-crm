Fulfilment planning: Preview inside the line grid, then Confirm

Mock v3 after the owner's hand test on build b51a4a40c (30 Sep): no extra section above the summary cards. The header CTA is Preview (N); Confirm N lines appears only after a preview has run. Preview mode filters the existing "Every contributing line" grid to exactly the rows the press will post and adds a Flow column: what goes to Purchasing (Order Inquiry) and what becomes a Stock transfer. Held-back rows are grouped apart with a tag. The Stock transfers grid above stays the transfer list and shows the transfers the press would propose. Exit preview returns the full list. Nothing writes until Confirm. No popup, no autosave.

1Header: Preview is the CTA; Confirm appears after it

Before a preview the header has one primary button, "Preview (3)". After the preview loads, it becomes "Confirm 3 lines" (primary) with "Exit preview" beside it; the count follows the ticks in the grid. Any change to the board after the preview (save, undo, refetch) drops Confirm and brings "Preview (N)" back.

Flow column rule: one tag per thing the server would write for that line. An Order Inquiry row = "Purchasing · <verb> <qty>" (ORDER, ORDER_BACK, RESERVE ...). A stock transfer = "Stock transfer · <from> to <to> <qty>". A line can carry both. The held-back and not-sent groups are never mixed into the ticked rows. Decide, Save all suggested and Undo all are disabled while in preview; Exit preview brings them back.
