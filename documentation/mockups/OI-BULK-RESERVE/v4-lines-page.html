Reserve from the cross-OI Lines page (OI-BULK-RESERVE, mockup v4)

v4 answers the owner's 15 Oct night note: sales asks CS to reserve on ~100 order inquiries, then the stock person reserves them from Order inquiries › Lines without opening each OI. It reuses v3's Decide (N) control and menu (Reserve as requested / Reject...) and the page's existing filter popover and chips. Dev OIs from the behaviour card (OI-2609-0730, OI-2609-0731, OI-2609-0718); the other OI numbers and every person name are masked or illustrative. Dashed amber outline = new element.

1Lines view: a new "Reserve" filter in the Filters popover

Same four words as the Documents view's reserve status (orderInquiryHeaderStatus.ts 25-41): Parked request to reserve, Needs reserve, Parked reserve, Reserved. Here it filters LINES (a line matches when one of its request rows is in that status). The stock person picks "Needs reserve": every line CS was asked to reserve and has not answered, across every OI.

Commit: one reserve-commit per OI, not a new multi-OI endpoint. The route is already one transaction per OI (order_inquiries.py 1300-1310: one db.commit(), rollback on any error) and the service resolves rows inside THAT inquiry only, so "all or nothing per OI" comes for free; a new endpoint would need a savepoint per OI to give the same answer. Omitting warehouse_id already defaults to the request row's own location (service 858), so the page does not need each request's warehouse. Calls run a few at a time; every call settles to saved or not saved with the server's message, so the dialog always ends on Close.
