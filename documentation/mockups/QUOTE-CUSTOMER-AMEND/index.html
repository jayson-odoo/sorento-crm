Both sides of a customer amendment request. ALL codes, descriptions and prices are FAKE (public repo); the shape is a real project quotation's: a priced item followed by zero-priced companion lines at the same quantity. Customer A, Project P1, Quotation No. PRJQ-0000-R1 (placeholder number, label per the QUOTE-SIGN-PAGE ruling), 40 lines, RM 250,000.00; seven lines shown. The minimum price on line 1 (RM 390.00) is illustrative. The sign page shell follows main today; QUOTE-SIGN-PAGE is reshaping it, so the shell is re-fitted after that merges, while the line editing, states and staff panel are what this mock asks you to approve. Answers assumed: Q1 (a) sign waits, Q2 (a) qty 0 = remove, Q3 (a) draft revision, Q4 (a) existing notification, Q5 (a) note kept.

1Customer: "Suggest changes" mode on the sign page, 1280px

The page is the quotation as issued. "Suggest changes" turns the qty and unit price cells into inputs on every line; description, code and spec stay plain text (no input exists for them). An edited line turns amber and keeps the issued value struck through underneath. Qty 0 marks the line as a removal. Zero-priced companion lines (line 2) have a qty input but no price input: their money sits on the parent. Sign is hidden while in this mode, so the customer cannot sign and suggest in one go.

5Staff: the request on the quotation document, 1280px

The quotation document page shows a "Customer request" card on top of the Signatures tab, with a count on the tab. Rows are the AmendmentDeltaTable in a new quotation mode: one row per changed field, issued → requested, the change, and Accept / Reject per row. A requested price under the line's stored minimum carries the "Below minimum" badge, which says the revision will need approval. Reject takes an optional reason that the customer sees. Apply is enabled once every row is decided.
