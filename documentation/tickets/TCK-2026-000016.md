# TCK-2026-000016 — Promotion MCP: drop discount fields + dynamic `access_levels`

> **Source ticket:** `TCK-2026-000016` (status: draft)
> **Priority:** high · **Category:** feature
> **Dependencies:** none (self-contained).

## Goal

Two changes:

(a) Trim the `crm_marketing_promotion_products_list` response: drop `discount_amount` and `discount_percent`; rename `promotion_price` → `selling_price`.

(b) Enforce `access_levels` as a required input across ALL `crm_marketing_promotion_*` tools — but the valid values are **dynamic** per contact (rows activate/deactivate in `contact_access_levels` over time). Static enum in the tool schema is wrong. Use a **two-call resolution pattern**:

1. Agent calls tool with no `access_levels` (or empty) → BE returns `422` with the contact's currently-active allowed list: `[{code, description}]`.
2. Agent picks 1+ from that list and re-calls. BE validates that EVERY passed code is currently active for the `(contact_id, space_id)`; otherwise `403` with the refreshed allowed list.

| `sorento_crm_backend/app/api/v1/marketing/promotions.py`, `promotion_products.py`, `promotion_attachments.py` | Accept `access_levels: list[str]` query param. Validation: missing/empty → 422 with `allowed: [...]`. Any code not currently active for contact → 403 with `allowed: [...]`. |
| `sorento_crm_backend/app/services/access_service.py` (or equivalent) | Add `resolve_active_access_levels_for_contact(contact_id: str, space_id: str) -> list[dict]` returning `[{code, description}]` filtered by `is_active=True`. Source: `contact_access_levels` joined to access-level master. |

## Step-by-step

1. Add service helper `resolve_active_access_levels_for_contact`. Make sure `is_active` (and any `effective_at`/`expires_at`) filtering is correct so deactivated rows never appear.
2. In each affected BE route, parse `access_levels` (CSV or repeated). If missing → raise `AppException(422, {detail:"access_levels required", allowed: resolve_active_access_levels_for_contact(...)})`.
3. If non-empty but any code is not in the active set → `AppException(403, {detail:"access_levels not permitted for this contact", allowed: ...})`.
4. Otherwise filter promotion query by `access_levels` (intersect with the promotion's `access_levels` column).
5. MCP `server.py`: shape `crm_marketing_promotion_products_list` response — drop discount fields, rename promotion_price.
6. MCP `catalog.py`: rewrite tool descriptions to document the two-call protocol verbatim so the AI agent has no ambiguity.

## Acceptance

- `crm_marketing_promotion_products_list` without `access_levels` → 422 body includes the contact's live allowed list (codes + descriptions).
- DB toggle: set one access level row's `is_active=false` → next probe's `allowed` list excludes it.
- Pass a deactivated code → 403 with refreshed allowed list (NOT the old cached list).
- Valid call → response has no `discount_amount`, no `discount_percent`, has `selling_price`.
