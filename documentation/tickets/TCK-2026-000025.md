### Slim shape

Rename:
- `picking_number` → `document_number`
- `picking_date` → `receiving_date`

Drop:
- `inspection_status`
- `inspection_date`
- `inspected_by_user_id`
- `quality_remarks`
- `picking_status`
- `picking_type` (always `goods_received` for GRN; redundant)
- `source_entity_type`, `source_entity_id` (internal)
- `picked_by_user_id` (id without name; surface via name only)
- `total_items_picked`, `total_items_discrepancy`, `total_cost` (none of these are user-relevant for the AI agent)

Keep:
- `document_number`, `spo_number`, `receiving_date`, `notes`, `picking_lines`, `lines_count`, `created_at`, `updated_at`

## Step-by-step

1. In `catalog.py`, add `limit` to the input schema with default 50, cap 200. Update tool description.
2. In `server.py`, write `_slim_grn_response()` - handle dict + list payloads, recurse into `data`/`grns`/`items`.
3. Wire by tool-name prefix check (`crm_procurement_grn_`) in `_sanitize_tool_response()`.
4. For product filter: when caller passes `product_query`, call the shared helper (top-k embedding on `source_type=product` → candidates → ilike on `(picking_lines.product_code, .product_name, .product_description)` via the BE filter param).

## Acceptance

- `crm_procurement_grn_list` with no args → returns up to 50 rows, no error.
- Response keys for each row are exactly the "Keep" list above; no key in the "Drop" list appears.
- Product filter accepts shortform code and returns hits.
