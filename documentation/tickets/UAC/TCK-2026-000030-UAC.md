# UAC - TCK-2026-000030 - Conversation SLA daily summary via WhatsApp

Spec: [../TCK-2026-000030.md](../TCK-2026-000030.md). Worker required for send criteria. See [protocol](./README.md).

## Functional

- [ ] **AC-30-F1 [F] - Bounded template summary when opted in.**
  Given a user with `notify_whatsapp_summary=True` + linked contact,
  When `run_user_sla_daily_summary` runs,
  Then exactly one `respond_io` send of the `sla_daily_summary` template is enqueued with bounded params (`outstanding`, `escalated_last_24h`, `resolved_last_24h`) + a deep link; no free-form long text.
  **Validate:** `pytest tests/test_sla_daily_summary.py::test_whatsapp_summary_template_enqueued`

- [ ] **AC-30-F2 [F] - Gating skip is graceful.**
  Toggle off OR no linked contact → no WhatsApp summary; email (`daily_sla_summary_subscribed`) + in-app summary unchanged.
  **Validate:** `pytest tests/test_sla_daily_summary.py::test_whatsapp_summary_skip`

- [ ] **AC-30-F3 [F] - Self-scoped for everyone (no roll-up).**
  A director and a regular user both get a summary scoped to their own assigned/outstanding rows; no team-wide aggregate is sent by the summary job.
  **Validate:** `pytest tests/test_sla_daily_summary.py::test_self_scoped_no_rollup` (director's counts == their own rows only).

- [ ] **AC-30-F4 [F] - Independent toggles.**
  `notify_whatsapp_summary` governs only the digest; `notify_whatsapp` (escalation/assign) is unaffected. All four on/off combinations behave correctly.
  **Validate:** `pytest tests/test_sla_daily_summary.py::test_summary_toggle_independent_of_escalation_toggle`

- [ ] **AC-30-F5 [F] - Deep link resolves.**
  The template's deep link opens the user's SLA summary view in the CRM (no UUID in the visible link text).
  **Validate:** Playwright MCP - open the deep-link URL pattern → lands on the summary view authenticated; param resolves to human-readable.

## Business

- [ ] **AC-30-B1 [B] - Counts accurate.**
  The three template counts equal the user's actual outstanding / last-24h-escalated / last-24h-resolved figures.
  **Validate:** `pytest tests/test_sla_daily_summary.py::test_counts_match_raw_data` (seed known rows, assert params).

## Scalability

- [ ] **AC-30-S1 [S] - One send per subscribed user, idempotent per run (XS1/XS5).**
  Each subscribed user gets exactly one WhatsApp summary per scheduled run; re-running the job for the same period does not double-send.
  **Validate:** `pytest tests/test_sla_daily_summary.py::test_one_send_per_user_no_duplicate_on_rerun`

## UX

- [ ] **AC-30-UX1 [UX] - Account toggle persists.**
  Account settings exposes the WhatsApp-summary toggle; toggling persists (PATCH) and survives reload.
  **Validate:** Playwright MCP - Account settings → toggle → assert PATCH in `browser_network_requests` → reload → state retained; no console errors. Vitest for the toggle component states.
