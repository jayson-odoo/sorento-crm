# UAC - TCK-2026-000033 - PWA + web push

Spec: [../TCK-2026-000033.md](../TCK-2026-000033.md). Worker required for delivery; VAPID keys required. See [protocol](./README.md).

## Functional

- [ ] **AC-33-F1 [F] - Installable.**
  Valid `manifest.webmanifest` (name, icons 192/512 + maskable, `display: standalone`, base-path-aware `start_url`); service worker registers + activates. Lighthouse installability checks pass.
  **Validate:** Playwright MCP - DevTools/Application: manifest parsed, SW activated. Or `npx lighthouse http://localhost:3000 --only-categories=pwa` (installability assertions).

- [ ] **AC-33-F2 [F] - Subscribe → push → click.**
  Granting permission creates a `web_push_subscriptions` row; a new in-app notification for that user produces an OS push; clicking it opens the deep link.
  **Validate:** Playwright MCP grant + subscribe (`browser_evaluate` on `pushManager`); `psql -c "select count(*) from web_push_subscriptions;"` ≥1; trigger a notification → `psql` shows `web_push` delivery `sent`; manual OS-push confirm noted.

- [ ] **AC-33-F3 [F] - Unsubscribe + prune.**
  Unsubscribe removes the row; a send to an expired endpoint (404/410) prunes that subscription.
  **Validate:** `pytest tests/test_web_push.py::test_unsubscribe_removes` + `::test_prune_on_410` (mock pywebpush 410).

- [ ] **AC-33-F4 [F] - Mirrors in-app, subscription = opt-in.**
  Whenever an `in_app` delivery is created for a user with ≥1 active subscription, a `web_push` delivery is also created. No separate pref column gates it. A user with no subscription gets no `web_push` delivery.
  **Validate:** `pytest tests/test_web_push.py::test_web_push_mirrors_in_app_when_subscribed`

- [ ] **AC-33-F5 [F] - No API caching; shell offline.**
  The SW never caches `/api/v1/*`; the static app shell loads offline.
  **Validate:** Playwright MCP - offline mode: shell loads; an `/api/v1/*` request while offline fails (not served stale). Inspect SW cache rules.

- [ ] **AC-33-F6 [F] - Base-path correctness.**
  `start_url` + SW scope honour `NEXT_PUBLIC_BASE_PATH`.
  **Validate:** build with a non-empty base path; assert manifest `start_url` + registered SW scope include it.

## Business

- [ ] **AC-33-B1 [B] - Normal user gets notification with app closed.**
  A normal user on a supported device (desktop, or iOS 16.4+ after A2HS) receives an SLA/notification push without the app open.
  **Validate:** documented manual check (device matrix incl. iOS A2HS); desktop path automated where possible via Playwright + worker-delivered push.

## Data

- [ ] **AC-33-D1 [D] - Schema + dep.**
  `web_push_subscriptions` (user_id, endpoint, p256dh, auth, ua, created_at) exists; `pywebpush` in `requirements.txt`; VAPID env documented.
  **Validate:** `psql -c "\\d web_push_subscriptions"`; `grep pywebpush requirements.txt`.

## Scalability

- [ ] **AC-33-S1 [S] - Async send + bounded growth (XS1/XS4).**
  Web-push sends run on the worker; delivery loops per active subscription; dead endpoints are pruned so the table doesn't grow unbounded.
  **Validate:** `pytest tests/test_web_push.py::test_send_async_and_prune`; confirm an index on `web_push_subscriptions.user_id`.

## UX

- [ ] **AC-33-UX1 [UX] - Enable-notifications flow.**
  An "Enable notifications" control triggers the permission prompt and subscribes; clear enabled/disabled state; no console errors.
  **Validate:** Playwright MCP - click control → permission flow → subscribed state reflected. Vitest for the control's states.
