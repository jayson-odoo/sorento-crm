# UAC - TCK-2026-000028 - Form SLA auto-scan fix + manual escalate

Spec: [../TCK-2026-000028.md](../TCK-2026-000028.md). Validate each before marking `[x]`. See [protocol](./README.md).

## Functional

- [ ] **AC-28-F1 [F] - Auto-scan escalates tier 2 → tier 3.**
  Given an unresolved form tracker at `current_tier=2` whose `due_at_resolution < now`,
  When `scan_overdue_and_escalate()` runs,
  Then it becomes `current_tier=3`, reassigned to a tier-3 member, with one new `escalation` event log (`from_tier=2,to_tier=3,trigger='auto'`).
  **Validate:** `pytest tests/test_form_sla_escalation.py::test_scan_escalates_tier2_to_tier3`

- [ ] **AC-28-F2 [F] - Self-idempotent: no double escalation.**
  Given a tracker just escalated (clock reset, `due_at` in future),
  When the scan runs again immediately,
  Then no further escalation occurs (tier unchanged, no new event log).
  **Validate:** `pytest tests/test_form_sla_escalation.py::test_scan_idempotent_after_escalate`

- [ ] **AC-28-F3 [F] - Top tier stops.**
  Given an overdue tracker at the policy's highest tier (no next tier),
  When the scan runs,
  Then no escalation, no event log, row stays open.
  **Validate:** `pytest tests/test_form_sla_escalation.py::test_scan_top_tier_no_escalate`

- [ ] **AC-28-F4 [F] - Manual force-escalate (pre-breach), all 4 form types.**
  Given an in-progress tracker not yet overdue for `complaint`, `stock_inquiry`, `purchase_request`, `sponsorship_form`,
  When a permitted user `POST /api/v1/sla/form-tracking/{id}/escalate {reason}`,
  Then `current_tier+1`, reassigned per policy, one `escalation` log with `trigger='manual'`, `triggered_by_id=<actor>`, `reason=<text>`; new assignee notified (in-app + email).
  **Validate:** `pytest tests/test_form_sla_manual_escalate.py` (parametrized over the 4 types) + `curl` smoke from spec.

- [ ] **AC-28-F5 [F] - Manual guard rails.**
  Manual escalate on top tier → 422; on resolved row → 422; when next tier has no resolvable assignee (no agent_id / no team / empty pool) → 422 and **tracker unchanged**.
  **Validate:** `pytest tests/test_form_sla_manual_escalate.py::test_422_paths` (asserts row state unchanged after the no-assignee 422).

- [ ] **AC-28-F6 [F] - Shared escalation path.**
  Auto and manual produce identical event-log + tracking field shape (both call `_escalate_tracker`); only `trigger`/`triggered_by_id`/`reason` differ.
  **Validate:** `pytest tests/test_form_sla_escalation.py::test_auto_and_manual_same_shape`

## Business

- [ ] **AC-28-B1 [B] - Escalation reaches management tier end-to-end.**
  A complaint escalated repeatedly (auto or manual) progresses 1→2→3 and lands on the tier-3 (management) team - no longer frozen at tier 2 (the fixed bug).
  **Validate:** `pytest tests/test_form_sla_escalation.py::test_full_chain_to_top_tier`

- [ ] **AC-28-B2 [B] - System-owned scheduled escalation (not n8n).**
  The `form_sla_overdue_scan` scheduled task exists, enabled, runs on the worker via the heartbeat; no n8n call is involved in form-SLA escalation.
  **Validate:** `psql -c "select key,enabled,interval_unit,interval_value from scheduled_tasks where key='form_sla_overdue_scan';"` → enabled, 2 minutes. Confirm `_handler_form_sla_overdue_scan` registered (`grep register_handler.*form_sla_overdue_scan`).

## Data / storage

- [ ] **AC-28-D1 [D] - trigger columns persisted.**
  `conversation_sla_event_logs` has `trigger` (`'auto'|'manual'`, default `'auto'`) + `triggered_by_id` (nullable FK users). Auto escalations → `trigger='auto'`, `triggered_by_id` NULL; manual → `'manual'` + actor id.
  **Validate:** `psql -c "\\d conversation_sla_event_logs"` shows columns; query after F1/F4 confirms values.

- [ ] **AC-28-D2 [D] - Rollout reset, no burst.**
  After the deploy migration, unresolved trackers at `current_tier>=2` have `current_tier_started_at` reset to deploy time and `due_at`/`due_at_resolution` recomputed; the first post-deploy scan tick escalates none of them solely due to the guard removal.
  **Validate:** migration test: seed frozen overdue tier-2 rows, run migration, run one scan → assert 0 immediate escalations from the reset rows.

## RBAC

- [ ] **AC-28-R1 [R] - Broad grant, gated.**
  `sla.form.escalate` granted to all roles; a user with it can escalate; a principal lacking it → 403.
  **Validate:** `pytest tests/test_form_sla_manual_escalate.py::test_rbac_denied_without_perm`

## UX

- [ ] **AC-28-UX1 [UX] - Detail-page SLA section + escalate modal.**
  On each of the 4 detail pages the SLA section always renders (empty state "No active SLA stage" when none). Escalate opens a modal with a **required** reason; submit → tier bumps in UI + success toast; no console errors; network shows the escalate POST.
  **Validate:** Playwright MCP - sidebar → Complaints → open one → SLA section → Escalate → submit; assert tier + toast + `browser_console_messages` clean + `browser_network_requests` has the POST. Vitest: `FormSlaEscalateButton` loading/empty/error/submit states.

## Scalability

- [ ] **AC-28-S1 [S] - Scan is set-based (XS2).**
  With ≥200 unresolved form trackers seeded, one scan pass issues a bounded number of queries (candidate fetch + per-escalation work only for actually-escalating rows), not O(N) per-row lookups for non-escalating rows.
  **Validate:** `pytest tests/test_form_sla_escalation.py::test_scan_query_count_bounded` (SQLAlchemy statement counter).
