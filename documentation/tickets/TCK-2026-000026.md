# TCK-2026-000026 — Embedding: customer + transporter coverage

> **Source ticket:** `TCK-2026-000026` (status: draft)
> **Priority:** high · **Category:** feature
> **Dependencies:** none. Foundational for TCK-2026-000017 and TCK-2026-000024.

## Goal

Cover two new embedding source types so RAG resolution surfaces customer + transporter terms:

1. **customer** — both from the `customers` master table AND seeded from distinct `(orders.debtor_code, orders.debtor_name)` so legacy debtor-only orders are searchable.
2. **transporter** — there is no master table today. Either (a) seed a thin `transporters` lookup table from distinct `orders.transporter` values, or (b) embed the raw string and hash-derive a stable source id. Recommendation: thin lookup table for stability + future linkage.

## Files to change

### Backend

- `app/services/embedding_worker.py` — extend `_canonical_for_source()`:
  - new `customer` handler: pull `customer_code, customer_name, country, contact_email, phone` from `Customer` (`app/models/order.py:46–86`); also seed-derive from distinct `(orders.debtor_code, orders.debtor_name)`.
  - new `transporter` handler: pull `transporter_name` (and `transporter_code` if you add it) from the new lookup table.
  - extend `order` chunk text (around line 320–329) to ALSO include `f"Transporter: {row.transporter or ''}"` so order chunks surface the transporter alias for downstream retrieval.
- `app/services/embedding_change_listener.py:129–140` — register listeners on `Customer`. Order is already registered; just extend the chunk text generation.
- New alembic migration: create `transporters` table — columns `id (uuid pk), code (unique), name, normalized_name, created_at`. Seed from distinct `orders.transporter`. Add nullable FK `orders.transporter_id` (keep `orders.transporter` string for now; backfill `transporter_id` lazily).

### Scripts

- `scripts/seed_customer_transporter_embeddings.py` — one-shot script to backfill historical embedding rows.

### Verification

- `POST /api/v1/external/rag/search` already exists (`app/api/v1/external/rag.py:39–78`). Use with `source_type=customer` and `source_type=transporter`.

## Step-by-step

1. Migration: create `transporters` table + FK column on `orders` (nullable); seed from `SELECT DISTINCT transporter FROM orders WHERE transporter IS NOT NULL`.
2. Extend embedding_worker source handlers.
3. Wire `Customer` SQLAlchemy listener so future changes auto-embed.
4. Run backfill script.
5. Smoke RAG search end-to-end.

## Acceptance

- `POST /api/v1/external/rag/search` with `{"query":"YOTU","source_type":"customer","top_k":5}` → returns customer hits including `YOTU BUILDER`.
- Same with `source_type=transporter` → returns transporter hits.
- Order chunks include the transporter alias so generic search `{"query":"<transporter-name>"}` also retrieves matching orders.
