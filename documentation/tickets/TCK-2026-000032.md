# TCK-2026-000032 - Management KPI dashboard (SLA task metrics)

> **Source:** directors' session 2026-06-17. "Dashboard for management to view the KPI of each task - make sure they are stored." Grilled 2026-06-17.
> **Priority:** high · **Category:** feature
> **Dependencies:** reads the event logs + the `trigger` field added by TCK-2026-000028. Assignee names benefit from TCK-2026-000031.

## Goal

A management-only dashboard surfacing SLA KPIs, with **both** team-wide aggregates **and** a per-task drill-down. The underlying data is already stored in `conversation_sla_event_logs` + `conversation_sla_tracking`; this ticket is the aggregation/query layer + the page, plus an audit that no KPI is silently uncomputed.

## Design decisions (from grilling)

- **"KPI of each task" = both:** aggregate KPI cards/trend/leaderboard **and** a **per-task DataGrid** - one row per SLA-tracked entity (complaint / stock_inquiry / purchase_request / sponsorship_form) showing its response time, resolution time, tier reached, escalation count (split manual vs auto via `trigger`), owner, and per-clock met/breach flags. Filterable.
- **Met/breach is split per clock:** two independent verdicts per task - **response met** = `responded_at <= due_at` (breach incl. never-responded past `due_at`); **resolution met** = `resolved_at <= due_at_resolution`. Report `% met` for response and resolution separately. A task can meet response but breach resolution.
- **Audience:** management/director only via new permission `sla.kpi.view`. Regular users do not see it.
- **Scope split:** conversation SLA vs form SLA partitioned on `source_entity_type ∈ FORM_SLA_TYPES`.

## KPIs

- Volume: opened, responded, resolved, escalated (escalated split manual/auto via `trigger`).
- Timeliness: avg/median response time, avg/median resolution time, **% response met**, **% resolution met**, breach counts per clock.
- Escalation: escalation rate, tier-distribution, count by tier reached, manual-vs-auto ratio.
- Leaderboard: per-assignee resolved count, avg response/resolution, breach counts (names resolved - **no UUIDs**).
- Outstanding: open/unresolved by tier + age bucket.
- Per-task table: the drill-down above.

## Background (verified)

- `ConversationSLAEventLog` (`app/models/sla.py:157`) stores `event_type`, `from_tier`/`to_tier`, `event_at`, `from_time`, `duration`, `response_time`, `resolution_time`, `reason`, `assigned_to_id`, `due_at`; **+ `trigger`/`triggered_by_id` from TCK-28**. Indexed on `sla_tracking_id`, `event_at`, `event_type`, `assigned_to_id`.
- `ConversationSLATracking`: `response_time`, `resolved_at`, `responded_at`, `due_at`, `due_at_resolution`, `is_responded`, `is_resolved`, `current_tier`, `source_entity_type`/`source_entity_id`.
- Existing widgets: `/api/v1/sla/.../dashboard` (`sla_tracking.py:242`), `/my-pending` (`:267`).

## Acceptance

- `GET /api/v1/sla/kpi/summary?scope=form&from=&to=` returns counts + avg/median response/resolution + `% response met` + `% resolution met` + breach counts; reconciles with raw event-log rows for a known window.
- `GET /api/v1/sla/kpi/tasks` returns one row per entity with both met/breach verdicts; manual vs auto escalations distinguishable via `trigger`.
- Leaderboard + task table resolve assignee UUIDs to names; no UUIDs visible.
- Conversation vs form scopes correctly partitioned.
- Page reachable via sidebar for management; 403 / hidden for regular users.
