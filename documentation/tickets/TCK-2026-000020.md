# TCK-2026-000020 — Attachments: Google-Drive dup-name + uniform replace-with-webhook-retrigger

> **Source ticket:** `TCK-2026-000020` (status: draft)
> **Priority:** high · **Category:** feature
> **Dependencies:** none. Self-contained.

## Goal

Two outcomes:

(a) **Google-Drive style** dup-filename behaviour: no two attachments may share `(directory_id, lower(original_filename))`. On upload collision, FE prompts "Create copy" / "Replace existing" / "Cancel".

(b) **Uniform replace + retrigger** across the four entity types that link to attachments:
- packing list → `inbound_shipments.attachment_id`
- promotion → `promotion_attachments.attachment_id`
- product → `product_attachments.attachment_id`
- marketing forms → `forms.attachment_id`

When the user picks "Replace existing", the attachment row is updated **in place** (same `id`, new bytes / `file_hash` / `file_size` / `uploaded_by` / `updated_at`), so all four linkages stay valid by FK. We then **retrigger the same n8n webhook** that fires on initial upload for that `target_entity_type` (payload carries `event_type="attachment_replaced"`), and the downstream intake endpoint **updates** the linked record instead of duplicate-rejecting.

## Files to change

### Backend — collision check at upload time

- `sorento_crm_backend/app/api/v1/resources/attachments.py:324–559` (`create_attachment`):
  - Before insert, lookup existing rows with same `directory_id` + `lower(original_filename)`.
  - If found:
    - `on_conflict="replace"` → update existing row in place; preserve `id`; re-publish embedding event; fire `event_type="attachment_replaced"` webhook for the entity type.
    - `on_conflict="copy"` → rename incoming to `name - copy.ext`, then `name - copy (2).ext`, … (loop until free); insert as new row.
    - `on_conflict` missing → return `409 Conflict` with `{existing_attachment_id, existing_file_name, existing_target_entity_type, existing_target_field_keys}`.

### Backend — uniform update paths in the four intake endpoints

- `sorento_crm_backend/app/services/procurement_service.py:504` (`create_shipment`):
  - Today raises 400 on duplicate `shipment_number` (lines 507–511). Switch:
    - existing shipment AND `shipment_status NOT IN ("fully_received","completed")` → update header + lines, set `shipment_status` accordingly. Notification email subject = `"Packing list updated"`.
    - else → reject with explicit "already completed, cannot update" message.
- `sorento_crm_backend/app/services/marketing_service.py:496` (`create_promotion`):
  - Mirror: if matching key already exists and still editable → update; else reject. Notification subject = `"Promotion updated"` vs `"Promotion created"`.
- Product attachment intake (n8n posts product spec sheets back via `/api/v1/external/product-attachments/...`): update path.
- Forms intake: update path.

### Backend — webhook dispatcher

- The dispatcher (locate near the existing upload webhook call site) accepts an `event_type` parameter. On `attachment_replaced`, target the SAME URL as the original upload trigger so n8n logic stays one path.
- Add a local-dev simulator: if `N8N_WEBHOOK_URL` is unset, log a canned response and run the local intake update path directly. Lets developers verify without n8n.

### Frontend — collision UX

- `sorento_crm_frontend/app/(protected)/resource-management/attachments/components/AttachmentUploadDialog.tsx`: on 409 response, surface `AlertDialog` with the three options. Re-POST with chosen `on_conflict`.
- Same UX on every upload surface: `components/template/TemplateUploadDialog.tsx`, promotion attachment uploader, product attachment uploader, forms uploader.
- Centralise via a shared `hooks/useUploadConflict.ts` so behaviour cannot drift.

## Step-by-step

1. **DB indexes:** add a partial UNIQUE index on `attachments(directory_id, lower(original_filename))` for rows where `directory_id IS NOT NULL`. Alembic migration.
2. Implement BE collision check + the three response paths (replace / copy / 409).
3. Update each of the four intake endpoints to handle update-instead-of-reject.
4. Implement webhook redispatch with `event_type=attachment_replaced`.
5. Wire FE shared `useUploadConflict` hook; integrate into all upload dialogs.
6. Update unit + integration tests for the four intake endpoints.

## Acceptance

- Upload `x.pdf` twice to same directory:
  - Choose "copy" → second stored as `x - copy.pdf` (new attachment row, independent linkages).
  - Choose "replace" → first row's storage key overwritten; all four linkage tables still resolve via the same `attachment_id`.
- Replace a **packing list** attachment → webhook fires with `event_type=attachment_replaced` → packing list lines updated (not duplicated); email subject `Packing list updated`.
- Repeat for **promotion / product / forms** — each linked record updates instead of rejecting.
- Re-upload packing list with same `(shipment_number, container_number)` and status `in_transit` → 200 + update. Same with status `fully_received` → 400 with `"already completed, cannot update"`.

## Manual verification

```bash
# 1) Upload twice — second should 409 without on_conflict
ATT_DIR=<some-attachment-dir-id>
curl -s -X POST http://localhost:8000/api/v1/resources/attachments \
  -H "Authorization: Bearer $JWT" -F "directory_id=$ATT_DIR" -F "file=@x.pdf"
# Second:
curl -i -X POST http://localhost:8000/api/v1/resources/attachments \
  -H "Authorization: Bearer $JWT" -F "directory_id=$ATT_DIR" -F "file=@x.pdf"
# Expect 409 + {existing_attachment_id,...}

# 2) Then replace
curl -i -X POST http://localhost:8000/api/v1/resources/attachments \
  -H "Authorization: Bearer $JWT" \
  -F "directory_id=$ATT_DIR" -F "on_conflict=replace" -F "file=@x.pdf"

psql -c "select count(*) from inbound_shipments where attachment_id='<aid>';"

```
