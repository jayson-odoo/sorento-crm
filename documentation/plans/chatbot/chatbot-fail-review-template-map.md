# System-failure reply map, customer-facing chatbot

Worktree app code = origin/main 4b9c52b153. Paths relative to `sorento_crm_backend/` unless they start with `sorento_crm_mcp/`. Lines were read in this worktree unless a row says "seed line, not re-read". UNVERIFIED = inferred, not read.

Conventions
- "failed turn" = `_failed_result` (engine.py:10940-10990): `status="failed"`, `reply={"text":..., "quick_replies":None}`, plus one `send_message` action carrying the same text. The caller (n8n or the inbox drain `_post`) sends it.
- Translation: EN text is the key; MS/ZH live in `app/services/chatbot/label_catalog.py` (static `LABELS` dict from :33, the failure sentences at :374-385, `INLINE` frozenset at :697; DB `translation_memory` rows can override, UNVERIFIED). `_localize_result` (def engine.py:2991, called engine.py:3787) only runs on a turn that returned normally out of `_run_stages`; the catch-all failure return (engine.py:3822-3828) and the earlier-message catch-all (engine.py:2557) skip it, so those are English only. A failure with no `item` (parser failure) has no `reply_language` and stays English too.
- Registry: `chatbot_reply_copy.CHATBOT_REPLY_COPY` (chatbot_reply_copy.py:488 onward) is the table of registry keys `chatbot_reply_<name>[.ms|.zh]`. NONE of the failure sentences below is in it (checked the dict: access_denied, offer_hold*, demand_qty, not_supported, clarify_menu, escalate_offer*, out_of_scope*, escalation_declined, offer_declined, plus `FALLBACK_REPLY_COPY` names). So every failure sentence is hard-coded; an owner edit in Settings > AI Prompts cannot change them. The one trap is F-CASUAL below (registry row exists but is not read on the failure path).
