SaaS patterns: adopted and rejected

AdoptedRejected (why)
600px table card on a soft background; logo header; preheader; one big centred bulletproof button (48px tall, full width on phones); raw link under it; 16px body with generous whitespace; facts as label/value rows; inline CSS; system fonts; footer with company, address, help and why-you-got-this; plain-text part; mobile-safe at 375 MJML/mrml (one fixed shell needs no compiler); hero and background images (blocked in Outlook); multi-column sections (cramped on phones); web fonts (Gmail/Outlook ignore them); social icon images (blocked); tracking pixels (not asked, a privacy cost on a security mail); dark-mode styles (out of scope); full drag-drop canvas (an ordered list does the job)

Open questions (recommendation in bold)

Q1 Supplier loading notice and container request: keep text-only in this PR? It is a bilingual EN/中文 cover note with the PDF and xlsx to external suppliers. Recommend: keep text-only now; brand it later if you want suppliers to see the card.
Q2 Password reset and invitation: big button plus the raw link underneath (the old reset mail showed only the raw URL, to look less like phishing). Recommend: button + visible link.
Q3 Footer social links as text, not icon images. Recommend: text links (icons are blocked by default in Outlook).
Q4 A system template switched inactive: still send with the built-in wording; stopping a mail stays the Email Event Configs switch. Recommend this, so a template toggle can never silently stop password resets.
Q5 Default brand colour #2563EB (the app's own blue) until you set one. Recommend this.
Q6 Default header: logo centred on the brand-colour band (the dreamz look). Alternative: white header with a hairline. Recommend the band.
Q7 An unknown variable still shows as [unknown:name] (helps spot typos in preview). Recommend keep for this PR.
