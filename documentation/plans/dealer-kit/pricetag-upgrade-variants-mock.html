5. Rules the mock follows (new since the card)

Q3: the template only says "Product: All variants". The request line decides which members: every product under the line's product (whole tree), all ticked by default, untick in the line's "Variants on this tag" select (SearchableMultiSelect). The line stores the UNTICKED members, so a variant added later joins ticked; a pinned tag freezes the members it printed.
Q5: the tag prints the line product's own LP / SP (hand-picked LP / SP / "LP & SP" as today). When the ticked members' list prices differ, the line shows "Variants price differently: RM x to RM y" under its price. Warning only; it never blocks Save or Approve.
Member specs, trap lengths and member prices are sample values (the owner's tag gives only SRTWC8354-SH: LP RM 1,750, SP RM 799); crew confirms them on the dev DB with the SQL in the card.
