Plan documentation/plans/scm/PLAN-scm-reorder-revamp.md + UAC alongside (written after this alignment) · new lane off main · 27 Aug 2026 · Status: ALIGNING (round 3, R1-R15)
GoalReorder planning works like fulfilment planning now does: a list of plans, one Start Plan, each product row expands into the whole decision (cover mix, MoQ, price, supplier, AutoCount level, product health), Save keeps drafts, one Confirm sends the plan. Every number on the row opens a lightbox that names the documents behind it.
Verified: "Live stock as of" is the request timelocation_stock_service.py:127 writes as_of = datetime.utcnow(). It stamps the moment the panel was opened, not the stock upload. The label will read the newest stock.updated_at for that product (fallback: the last stock import job's finished time) and say "Stock as of".
What stays exactly as it isThe engine and every frozen number. Decisions still land in scm.plan_row_decision, Confirm still writes draft purchase orders via confirm_decisions. The daily cron run still appears; it just shows up as a row on the list.

7. Save and Confirm FE + BE

Edits are local until Save Every input in the panel writes to a draft map keyed by rec id; the pill turns "Unsaved". Leaving the page with drafts prompts. This is the difference from today, where each pencil Record / MoQ blur / level Save / health click fires its own request.
Save (N) = one request New PUT /scm/reorder-runs/{run}/plan-edits with rows[{rec_id, decision?, moq?, level?, reorder_qty?, lifecycle?}], one transaction, calling the existing service functions (record_plan_row_decision, set_moq_override, level amend, record_lifecycle_decision). Grouped rows fan out to member recs as today. The per-row endpoints stay for the API.
Confirm (N) = Save, then confirm-decisions One button, last in the toolbar. Untouched rows confirm as the engine suggestion (the sibling rule); skipped rows are left out. Confirm dialog states the count and cash. Afterwards rows read Confirmed and the pill's mix is frozen; drafts POs raise as today.

10. Risks

  • Plan size. The grid loads the whole run client-side (4 unpaginated queries). A 400-row plan with every row expanded renders 400 panels; Expand all stays within the current page (50 rows) and the location table fetches live stock only for open rows, as today.
  • Last supplier vs shortlist. Purchase history names no destination for 12,928 of 12,940 PO lines, so "last supplier" is product-wide, not per segment. The row keeps saying which attribution it used (last_purchase_basis).
  • Unsaved drafts. A browser refresh loses unsaved edits; the pill count and the leave-page prompt make that visible. Nothing is auto-saved.
  • Legacy runs (no front_planning_contract_version) stay read-only: panel renders, inputs disabled, same lock reason as today.
