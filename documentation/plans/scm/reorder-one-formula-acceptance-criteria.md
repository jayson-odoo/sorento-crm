## Sheet Dealer o/s (S2)

- **AC-9** On a run carrying the channel snapshot, `OrderSummaryRow.dealer_outstanding` = sum of the product's recs' `inputs.retail_committed` (170 for B2155) even when the SO book holds 1381 open retail units outside the run's window. `dealer_outstanding_line_count` and `max_days_outstanding` come from the SAME window: `_demand_aggregates` takes the run's `plan_horizon_start`/`plan_horizon_date` and filters `required_date` exactly as `demand.horizon_committed_select_sql`'s book leg does (a NULL date always counts; a NULL bind lets everything through), so 8 open lines / 1381 units with 170 in window reads as 1 line, not 8. The window narrows the PROJECT half of the same read too (`project_demand`, `project_demand_line_count`) and that is deliberate: ONE window for the whole sheet, so two figures a reader compares on one row cover the same period. `_demand_aggregates` also matches the book leg's POPULATION, not only its dates - a `purchasing_status = 'covered'` line is excluded and the outstanding quantity is `COALESCE(qty_required, qty_ordered) - qty_delivered` - because counting a line the plan's own committed figure excludes put a line count on the sheet beside a quantity that did not contain it. Legacy run (no snapshot): unchanged SO-book read. Test: `tests/scm/test_summary_order_service.py::test_dealer_outstanding_is_the_runs_horizoned_retail`.
- **AC-10** The exported sheet (PDF rows + xlsx rows) prints that figure in "Dealer o/s". Test: `tests/scm/test_order_summary_sheet.py::test_sheet_dealer_os_matches_grid_retail`.
