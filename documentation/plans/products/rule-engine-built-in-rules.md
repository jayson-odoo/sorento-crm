# Appendix - every built-in rule today, in the new rule engine's form (#1286)

**Companion to:** `PLAN-product-specs-non-technical-26sep.md` section 3 (the rule engine, D5).
**Measured on:** `origin/main` `51d30ccc5`, from `_rules_from_shipped_tables()` in
`sorento_crm_backend/app/services/product_spec_registry.py`: 50 specifications, 269 rules.
Brand (1 rule) is left out because the Brand specification goes away (owner ruling 26 Sep 2026,
Q1). The other 268 rules are all expressed below with the five kinds of rule and no pattern:

| Kind | Rules today | What it finds |
| --- | ---: | --- |
| Words | 231 | Words in the text, then gives the answer you pick |
| Number | 10 (+1) | A number next to a word (before, after, or between two words) |
| Size | 10 | One number out of a size such as 1500 x 750 x 630, or the one labelled L, W or H |
| Code | 12 | Something in the product code (contains, starts with, ends with) |
| Product | 5 | A fact already on the product (its category's class, its length, what its name says it is) |

Rules next to each other that give the same answer are shown as one rule with several words
("says X or Y or Z"). That is how the new screen stores them, and it keeps the run order, so 268
rows become 202 rules. "today row N" is the position in today's list, so each line can be checked
against the current screen.

**Fix round 1 (26 Sep 2026, the lane's parity run):** three shipped rules were corrected, so the
list now holds **203 rules**. Length gained rule 4, "the number between LENGTH and MM" (new, no
today row: "(LENGTH-200MM)" was read by today's lone-size pattern and the new engine's
stand-alone number never reads it). Hose length does not read a bathtub or jacuzzi ("BRAVAT
1.75M ... BATHTUB" is the tub). Number of bowls ships a highest believable value of 9, so "6086
BOWL ONLY" is flagged instead of stored.

Generated by a script that reads the shipped table (not typed by hand), so the list cannot drift
from the code it describes. Value names are shown the way the choice list shows them. How the
engine matches words and numbers (the same for every rule, not a setting): see plan D5.
