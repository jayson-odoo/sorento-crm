  1. 1
    PageHeader carries every read-only fact once. Schedule number and version, status pill, project, revision, dated, PO version it was checked against, read time. The five stacked blocks at the top of today's page (screen 10) collapse into this header plus tabs. Breadcrumb follows where the user came from (Needs attention or the project).Audit screen 10 ("five distinct concepts stacked in the first screen"). ADR "read-only metadata lives in the page header". Ruling R1(4).
  2. 2
    Record navigation plus one primary button. Prev/next walks the other versions waiting in the same list; Confirm schedule is the single primary action. After Confirm the user returns to where they came from. When confirmed, the pill reads Confirmed with who and when, and the button goes away; the explanatory sentence "This schedule is confirmed, so nothing here can be changed" is removed.Ruling R4 (slice S4). DESIGN-LANGUAGE D6. PRINCIPLES "no feature explanations inside the UI". Audit screen 11.
  3. 3
    Line tabs, one concern each, with counts. Matrix, Findings, Changes since v1, Re-dating, Notes. Today these are five sections in one scroll and the reader cannot tell how many cards follow (screen 13). The count is in the tab, so "20 changes" is known before opening it.Audit screens 10, 11, 13. DESIGN-LANGUAGE "Tabs with TabsList variant=line". Ruling R1(2), R1(4).
  4. 4
    View toggle, filter chips and one severity legend. By area / By date is a pill toggle (a view switch, not navigation). "Only columns to fix" defaults ON while the version is unconfirmed, so the 9 problem columns are the first thing seen instead of 35 reconciled ones. Statuses use the shared three-level severity set from slice S3.Audit friction #5 (severity words differ per surface). Ruling R3.
  5. 5
    Reconciliation merges into the matrix. The separate 9-row reconciliation table (screen 11) is gone; its status is a column of the matrix and its detail opens in the row card (8). One grid instead of two grids that list the same columns.Audit screens 11, 12, 14 (the "column card" was really the list row plus the highlighted matrix row). Ruling R1(4).
  6. 6
    "Area" replaces "Phase" in every label. Each schedule column that today reads "Phase" (Phase 1, Level 2 & 7) is an Area; the group above it is its Area group (Common area, Tower), shown as the column-group header so the two are visibly one hierarchy. The sales order's area group is copied from this same grouping, so mockup 3 uses the same words. "By phase" becomes "By area"; "0 phases moved" becomes "0 areas moved".Audit friction #6 (phase vs area group never tied together). Ruling R6.
  7. 7
    Totals in the table, under their column. Schedule and PO totals are DataGrid columns with a footer row, replacing the "Our total / Schedule / PO" figures repeated in each row card.ADR 1d ("a total belongs in the table").
  8. 8
    Row click opens the column card inline, with the full customer code. The customer code is never truncated here (it truncates in the grid with the full string on hover). The fix action is today's product picker; the dismissal is today's "Dismiss as false signal", renamed to the one verb "Dismiss with a reason" and rendered by the shared findings component.Audit friction #9 (raw codes truncated with no way to read them). Ruling R3. Code: DeliveryScheduleProductPicker, DeliveryScheduleReconciliationList.
