1. The ask

In your words, from the issue (26 Sep 2026):

"Looking at this Excel is the cost price of the product. So we need to allow the user to upload this. But I want to exploit a bit further with our current token capability, which is I want this to be a web page that can be access controlled because the supplier of Sorento is mainly from China. So probably they won't have WhatsApp, they will have WeChat. So I'm thinking instead of letting the user from Sorento upload the cost to our system, we can have a page for the supplier to maintain instead of them maintaining in the Excel. Of course, if they want to upload this Excel to the web page, it's also possible. But again, it needs to be more process control because we cannot let them directly upload and override our system cost price. There needs to be a verification process digitalized in the system. So I want first, the upload of this by the Sorento user is definitely a must. And I want us to also explore putting this process to the supplier and verify by Sorento internally before applying the change to the actual DB value. So which is why it's very important for the audit trail to exist for this also so that we can trace what happened."

The file: TAIYANG's price list of 17 Sep 2026, five sheets (19, 12, 22, 28 and 25 series), with model code, configuration and price columns.

2. Decisions made so far

Every ruling, word for word, with what it changes in the design.

26 Sep 2026, 23:45 MYT, question 1 (which price)
"yeah correct"
So: The price we update is each supplier's price per product, the one the reorder screen uses. The product's own MYR cost is not touched.
26 Sep 2026, 23:45 MYT, question 2 (currency)
"yeah correct, most is cny i believe in the file provided"
So: Prices stay in the supplier's currency with no conversion. TAIYANG's file is read as CNY.
26 Sep 2026, 23:45 MYT, question 5 (who may upload)

So: One new upload permission, given to every purchasing role, plus admin.
26 Sep 2026, 23:45 MYT, question 6 (who verifies)

So: When verification is on, one Sorento person decides, and it cannot be the person who uploaded.
26 Sep 2026, 23:45 MYT, question 7 (accept per line)
"yeap"
So: When verification is on, the verifier accepts or rejects each line, and can send the whole upload back with a reason.
26 Sep 2026, 23:45 MYT, question 10 (one open upload per supplier)
"yeah correct"
So: A supplier can have only one upload waiting at a time.
27 Sep 2026, 00:10 MYT, question 3 (dates)
"oh okay yeah we need that, like a date range, there will be end also if there needs to be, so it is like price list function in ERP system including Odoo, where 1 product can have different price list, so this is like 1 product supplier can have different cost list and the cost list can have start and end (optional), if both null then means always, if got start only then means no end, concept like that"
So: Each product and supplier pair gets cost lists: a price with an optional start and an optional end. Both empty means always. The price used today is the one whose range covers today with the latest start.
27 Sep 2026, 00:10 MYT, question 4 (what the price includes)
"oh this is raw price only, no include shipping tax terms"
So: The price is the raw unit price. There is no field for shipping, tax or terms anywhere.

So: Agreed: dropped. No suggestions. What the existing matching engine cannot match is picked by hand from a product dropdown.

3. What each slice ships, in order

Slice 1: Sorento staff upload the price list and apply it, into dated cost listsNeeds your hand test
BeforeMei Ling gets TAIYANG's Excel on WeChat and has to type 258 prices one by one into each product's supplier price. There is no way to say a price starts on 1 Oct.
AfterShe uploads the file, sets Valid from 1 Oct, searches the review page for anything odd, picks the one code the system could not match from a dropdown, and clicks Apply 212 changes. Each product now shows the new 1 Oct price as Scheduled, and it takes over on 1 Oct by itself.

Hand test: Yes: upload the real TAIYANG file, apply it, and look at TAIYANG's Prices tab.

Slice 2: Verification, built now and switched offNeeds your hand test
BeforeNothing stops one person changing a supplier price, and nothing records that anyone checked it.
AfterWith the switch off (the first rollout) nothing changes for Mei Ling. When you turn it on in System Settings, her Apply button becomes Submit for verification, and Kelvin accepts or rejects each line and applies. The record shows Verified by Kelvin, or Not verified.

Hand test: Yes, once: turn the switch on for one test upload and check a second person must apply it.

Slice 3: The supplier's own price pageNeeds your hand test
BeforeMr Chen at TAIYANG edits his Excel and sends it on WeChat; someone at Sorento uploads it.
AfterMei Ling sends Mr Chen a link on WeChat. On his phone he searches his models, sees each price and its dates, types new prices from 1 Oct, and taps Submit for review. It always waits for a Sorento person to verify it, even with the switch off.

Hand test: Yes: open the link on a phone.

Later: supplier loginNo hand test
BeforeThe supplier uses a link that expires after 30 days.
AfterWhen the new login for outside parties arrives, the supplier logs in instead of using a link. Same page.

Hand test: No, not in this plan.

4. Open questions

Numbered as in the plan. The plan and the checks are written to the recommendation in bold until you rule.

Question 16. Old ways of setting a supplier price. Purchase orders and the product import can still set a supplier price directly. For a product that has cost lists, what should happen?

Recommendation: Let the next overnight check put the cost list price back, and show both changes in the audit trail. No change to those screens for the first rollout.

Under the other choice: If instead they should add a cost list of their own, five existing screens change and each one writes an "always" cost list.

Question 11. The supplier's link. How long it lasts and what the supplier sees.

Recommendation: One link per supplier, valid 30 days, can be cancelled any time, no one-time code. The supplier sees only its own products, its own prices and dates, and whether each line was accepted.

Under the other choice: A one-time code would need SMS to China, which we do not send today.

Question 12. Language on the supplier page. Which language leads.

Recommendation: Chinese first with English beneath, and a switch. Staff screens stay English.

Under the other choice: English first would change only the supplier page.

Question 13. Other ways a supplier price changes today. Today any logged-in user can edit a supplier price, with no record.

Recommendation: Require the existing product supplier edit permission and record every change.

Under the other choice: Leaving it open keeps an unrecorded path next to the controlled one.

Question 14. Sending the link over WeChat. How the link reaches the supplier.

Recommendation: Staff send it from their own WeChat; the dialog gives the link, a QR image and a ready message.

Under the other choice: Sending from the system needs a WeChat business account we do not have.

Question 15. Who is told about a submission. Notifications when verification is on.

Recommendation: An in-app notice to verifiers when something is submitted, and to the uploader when it is applied or returned.

Under the other choice: No notice means verifiers must check the list themselves.

6. Out of scope and risks

Not in this plan:

  • Suggestions for codes the system cannot match ("did you mean"). Dropped per your question 8.
  • Packaging variants as a separate idea. Dropped; a code written twice in one file is simply flagged so one is skipped.
  • Converting prices to MYR, or changing the product's own MYR cost.
  • Creating a new product from a code we do not know.
  • Sending WeChat messages from the system, and a one-time code on the supplier page.
  • Pricing a future purchase order from a future cost list (screens use today's price).

Risks:

  • With verification off, one person can change a price. That is your ruling; every upload records "Not verified" and the switch itself is recorded.
  • A new price feeds the reorder screen straight away. The review page shows the largest rise before Apply.
  • If the overnight job does not run, a price scheduled for tomorrow starts late. The Prices tab still shows which price should be in force, and the job catches up.
  • The TAIYANG Excel itself has not been attached yet. It is needed before the build starts, to test against the real file.
