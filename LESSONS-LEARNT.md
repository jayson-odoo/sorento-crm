# LESSONS-LEARNT.md - gotchas worth remembering

The running log of hard-won, non-obvious gotchas: the stuff that cost real debugging time and
would cost it again. Append here when a bug's root cause was surprising or system-wide. Keep each
entry a single bolded claim + the mechanism + the fix, at most ~4 lines. `PRINCIPLES.md` governs;
`CLAUDE.md` is the per-engine reference; this file is institutional memory - it does not restate a
rule already stated in either of those.

> First extracted from `CLAUDE.md` on 2026-07-13, re-merged 2026-08-23, trimmed 4 Sep 2026 (rules
> since folded into `PRINCIPLES.md`/`CLAUDE.md` retired; standing gotchas compressed).
> Per-feature decision logs live with their plan in `documentation/plans/<domain>/`.

**Housekeeping.** When a lesson's cause is fixed in code, or a regression test in
`sorento_crm_backend/tests/test_lessons_learnt_regressions.py` guards it structurally against
recurrence, retire the entry. When it merely duplicates a rule already stated in `CLAUDE.md` or
`PRINCIPLES.md`, retire it there too - one copy, one place. This log is append-mostly, not
append-only, or it stops being readable.

## Active

- **Respond.io `contact_id` ≠ `respond_io_id`.** Portal/complaint/stock-inquiry/purchase-request `contact_id` columns store the internal `respond_contacts.id` (UUID); the Respond inbox URL and message API need `respond_io_id`. Always resolve via `RespondContact` before building inbox URLs or calling Respond.io.
- **`respond_inbox_url` must be set at row creation** for the admin chat panel to work, and excluded from any `_editable_fields` payload application - a portal `_instantiate` missing it renders an empty chat with no error.
- **Vitest + jsdom does not implement `scrollIntoView`.** Guard with `ref.current?.scrollIntoView?.({...})` so component tests don't TypeError.
- **`DataGridTable` DOES mount rows under jsdom** - `useListingColumnPreferences` fetches column prefs and renders skeletons until it answers, and nothing answers under jsdom. Mock it (`vi.mock('@/lib/listing-column-preferences/useListingColumnPreferences', ...)`) and rows/badges/pagination assert normally.
- **Don't silently duplicate chat/list panels across domains.** Complaint, stock_inquiry, purchase_request all share the Respond chat panel via `components/common/RespondChatList.tsx` so ticks/dates/selection can't drift across the three.
- **AI assistant tool dropdown is sourced from the live MCP server, not the DB catalog.** Adding a tool to `sorento_crm_mcp.catalog.CATALOG` needs an MCP process restart to show up in `/api/v1/system/ai-assistant/tools`. `mcp_tools` (DB) is for AccessAgent ownership only.
- **A tool that doesn't proxy a CRM HTTP endpoint needs `external=True` on `ToolSpec`**, or `_compile_tool` 404s building an HTTP impl from `spec.method`/`spec.path`. Register the real impl separately (see `register_user_guide_tools`).
- **AI assistant chat renders raw text by default** - wrap in `ReactMarkdown` (`AIAssistantBubble.tsx`) or `**bold**`/links/lists show as literal characters. Internal links (`href` starts with `/`) route through `next/link`.
- **Guide-menu paths are annotated with markdown links to FE routes, not resolved at runtime.** Add new paths to `scripts/annotate_user_guides_routes.py` and re-run (idempotent).
- **User guides live in Outline at runtime, not the repo.** `documentation/user-guides/` is the editable copy; two-way sync via `scripts/sync_user_guides_outline.py push|pull` plus a 6h cron PR.
- **AI assistant must READ a guide before answering "how to"** - `user_guides_search` then `user_guides_read` then quote the steps with links intact, enforced by the **USER GUIDE PROTOCOL** system-prompt addendum, never just paste the doc URL.
- **Outline's web editor silently strips query-bearing markdown links on next save**, even though the API-pushed version stores them correctly - drops the moment a human opens+saves the doc in Outline UI. Verify via `documents.info` API immediately after any sync, never trust Outline's rendering; prefer `#fragment` deep-links over `?query` ones since fragments aren't in Outline's link-validator path.
- **`re.sub` replacement strings parse `\X` as backreferences.** Injecting a URL via `re.sub(pattern, f"...{url}...", text)` raises `re.PatternError` if `url` contains a literal `\u`/`\g`/`\1`-`\9`. Wrap in a lambda (`pattern.sub(lambda m, r=replacement: r, text)`).
- **Tailwind v4 `--primary` resolves to `oklch(...)`, not `H S% L%`** - `hsl(var(--primary) / 0.55)` is invalid CSS, silently dropped. Use `color-mix(in oklab, var(--primary) X%, transparent)` for alpha overlays.
- **`GuideTargetSpotlight` needs a `MutationObserver` fallback for dialog-internal targets** - buttons inside `Dialog`/`Popover`/`DropdownMenu` only mount when the user opens the parent, so a fixed retry window expires first. Current strategy: rAF -> 5×200ms retry -> `MutationObserver` up to 30s (`app/components/common/GuideTargetSpotlight.tsx`).
- **Re-injecting a guide-authored deep link after LLM paraphrase needs a dynamic map, not the static `_ROUTE_MAP`.** The LLM often drops `[**Upload**](?guide_target=...)` to plain `**Upload**`; `_extract_guide_link_map(tool_calls)` scans tool outputs for every `[Label](URL)` pair and feeds it as `extra_map`, bold-only so a stray prose verb never gets auto-linked.
- **Two SLA systems share `conversation_sla_tracking`, discriminated only by `source_entity_type`.** Conversation SLA (n8n, one open per contact) has it NULL; form-SLA stage rows (per-entity, multi-active) have it set. Every contact-keyed query MUST filter with `conversation_tracking_scope()` (`sla_service.py`) or it falsely matches a form row - the original bug: an active form row 409'd n8n's conversation create.
- **Conversation-SLA create is idempotent, not 409.** Active row -> 200 with `already_active: true`, clocks/assignee untouched. Resolved row -> overwrite-in-place (event-log history survives, FK'd by tracking id). DB-level singleton via a partial unique index.
- **`create_event_log` interprets a NAIVE datetime as Malaysia time (UTC+8), but tracking columns store naive UTC.** Passing `tracking.due_at` straight in silently shifts it -8h. Wrap with `_to_aware_utc()` first.
- **Tests run on Postgres ONLY (PRINCIPLES.md governs the rule; this is the fixture-level detail).** `tests/_pg_fixture.py`: `blank_session()` for an isolated blank schema, or `SessionLocal` inside a rolled-back transaction. Seed REAL FK targets - Postgres enforces constraints sqlite would have silently ignored. Mock-chain tests (`qm.filter.return_value = qm`) break silently when a query gains `.order_by()`.
- **CI's database has NO data (PRINCIPLES.md governs the rule).** The local `DATABASE_URL` is a prod copy, so a borrowed `LIMIT 1` lookup resolves to something real locally and `None` on CI - one borrowed lookup produced 16 failures once. Every test seeds its own chain with a marker prefix; if the suite needs genuinely shared reference data, run the seeding migration's `upgrade()` in a rolled-back transaction rather than assuming a live row.
- **A migration-seeded reference table needs `__company_shared__ = True`, or its own seeds are invisible to a scoped user.** `build_company_predicate` (`app/services/company_scope.py`) compiles an owned table to `company_id IN (scope)`, excluding NULL-company migration rows; only `__company_shared__` adds `OR company_id IS NULL`. Symptom reads as an auth bug (API-key caller sees the seeds, logged-in user sees none) rather than a scoping one.
- **Suffixed NextAuth session cookie breaks `getToken` -> refresh-logout.** `NEXTAUTH_COOKIE_SUFFIX` renames the cookie so :3000/:3001 don't clobber each other, but any `getToken()` caller using the default name finds nothing -> 401 after a hard refresh while `/api/auth/session` still looks fine. Single source of truth: `lib/auth-cookie.ts` `sessionTokenCookieName()`, passed as `cookieName` everywhere - never hardcode `next-auth.session-token`.
- **Deep-link-after-login is the `(protected)` layout's job**, redirecting to `/signin?callbackUrl=<pathname+search+hash>` - capture the full relative URL or query strings get dropped. Portal contact links (`/view`, `/portal`) live under `(auth)`, a separate NextAuth-independent flow.
- **Every Respond.io send must write an `integration_log` on success AND failure**, even a 401 from bad local creds - mirror `_send_and_log`. The raised exception is stamped with the actually-attempted payload so the outbox shows the truth. `integration_log.business_id` is a UUID column - use `notification.id`, never a composite string.
- **Respond sends use the WORKSPACE key, not env `RESPOND_API_KEY`.** `RespondClient.for_identifier(...)` resolves the per-contact/default workspace key first; the env key is a deprecated last-resort fallback. A bad workspace key 401s every send while `settings.respond_api_key` stays valid.
- **Form-SLA stage is identified by `(source_entity_type, team_set_code)`**, not tier alone - `AccessAgentService.resolve_team_with_tier_fallback(agent, start_tier, team_set)` walks up from the tracker's tier to the first team that exists, used by both initial assignment and escalation so a missing intermediate tier is skipped, not fatal.
- **SLA notify is a matrix: stage bool AND per-user event toggle.** Stage `notify_assignee`/`notify_on_escalation` gate the event; per-user `notify_email_on_{assignment,escalation}`/`notify_whatsapp_on_{...}` gate the channel. In-app always sends when the stage allows; WhatsApp additionally needs a linked RespondContact.
- **Staff team-notification emails link to the in-system detail page, never the public `/view?token=` page** - recipients are internal staff and the deep-link-after-login carries them back post-login. Each entity keeps `_build_*_internal_url` separate from `_build_*_view_url`.
- **Status pill colour is centralized in `lib/status-pill.ts`** (soft pastel), reused across PR/SF/stock-inquiry list + detail. `getDisplayStatus` must prioritize the terminal lifecycle `status` over `approval_status` or list/detail/portal disagree.
- **react-query staleness on entity mutation: key dependent queries on the entity's changing field** (e.g. `updated_at`/`status`), not just the entity id - otherwise a banner reflecting a spawned SLA stage shows the OLD stage's reason until a manual refresh.
- **MCP `updated_at` must be emitted as naive Malaysia wall-clock, not offset-aware `+08:00`.** An aware `...+08:00` gets re-converted back to UTC by downstream n8n/luxon consumers, undoing the conversion. Fixed generically at the `updated_at` key in `_sanitize_tool_response`, not per-tool.
- **Complaint <-> DO auto-fulfilment invariants.** (1) "Delivered" needs BOTH `actual_delivery_date` set AND `order_status` in {delivered, completed}. (2) The auto-linker only touches `LINKABLE_STATUSES = {processed_by_cs, fulfilled}` - a `submitted` complaint won't retro-link without a re-save of the DO. (3) The team delivery email sends ONE email per member as To - CC recipients were silently dropped. (4) Notify tiers: DB -> env -> default `1,2`.
- **MCP stock-balance hides on-hand=0 rows zeroed by a `SYSTEM_ADJUSTMENT`** via `exclude_zero_system_adjustment=true` (default true for MCP, false for the FE list) - a genuine 0 from a real sale/import is still returned.
- **AI assistant prompts live in a DB registry (`app/services/ai_prompt_registry.py`), not hardcoded.** Immutable versions + movable `production`/`staging` labels; `get_prompt(db,name,label)` TTL-caches with a hardcoded fallback when DB-unreachable. `config.system_prompt` is deprecated/read-ignored - the `agent_system` registry key is the source of truth.
- **The prompt dry-run (`.../prompts/{name}/test`) runs the WHOLE assistant turn end-to-end**, not a single node - you see only the final synthesizer answer, using the SAVED selected version (not the unsaved editor buffer), and it strips write-capable MCP tools (`*_submit`/`*_create`/`*_link`) so a test can't persist a real record.
- **Prompt-registry save-validation returns a TOP-LEVEL body, not the `AppException` envelope** - `POST .../prompts/{name}/versions` on an unknown `{{token}}` bypasses `response_model` via a raw `JSONResponse` (`422 {error, unknown_tokens, missing_vars}`). FE must read those fields directly, not via `extractApiError`.
- **Form handling-lock "escalated" = `escalated_at` stamped, NOT `current_tier > 1`.** Some form-SLA configs START above tier 1 (project_sales begins at tier 2; PR/SF routes to a default approver at their own tier) - a fresh, never-escalated tracker can legitimately sit at tier 2/3. Gate on `escalated_at` everywhere (FE `resolveHandlingLockState`, BE `handling_lock_service._is_escalated()`), set only by `_escalate_tracker`.
- **The in-form lock banner and the SLA-escalation banner are TWO separate queries** - a manual "Escalate" must invalidate both (`useHandlingLock().refresh()` alongside the SLA query) or the lock banner lags a reload even though the SLA banner updates live.
- **An `async def` route that never awaits blocks its WHOLE worker's event loop** - symptom is a 504/queuing pattern (measured 61s apart), not one slow response, because prod runs 4 gunicorn workers and one blocks for the handler's duration. Fix is plain `def` (anyio threadpools it) or `run_in_threadpool`, capped to the DB pool or 504s just become "too many clients". ~40 handlers remain unconverted (BL-009) and the pattern decays back in - treat new heavy sync work in `async def` as a defect on sight.
- **On macOS an RQ work-horse SEGFAULTS the moment it opens a NEW psycopg2 connection**, if the parent already touched XPC/GSS (`ENABLE_SCHEDULER=true` guarantees this). RQ reports only `waitpid returned 11`; the job never marks failed and its row stays `processing` forever. Fix: `PGGSSENCMODE=disable`. A second, distinct fork-unsafe path (`getproxies()` via boto3/requests) needs `no_proxy='*'`. Linux is unaffected.
- **A docstring asserting a performance number is load-bearing and goes stale silently.** A flyer-read docstring claimed "~1s, stops holding at ~10s"; measured reality was 17-18s and nothing caught the drift because nothing failed. Record what a number was measured against, and re-measure before reusing it in a new design decision.
- **One container, several suppliers: `inbound_shipment_lines.supplier_id` owns the line.** Line key is `(shipment_id, product_id, supplier_id) NULLS NOT DISTINCT` (migration 374); an upload replaces only its own supplier's lines. Header `supplier_id` is DERIVED (mixed suppliers -> NULL) - never filter shipments by the header alone, use `shipment_supplier_predicate`.
- **A reusable `exists()` predicate needs an explicit `.correlate(<parent>)`** when shared across queries of different shapes - `shipment_supplier_predicate` auto-correlated fine standalone but raised "no FROM clauses due to auto-correlation" once nested inside a query whose outer FROM was already a subquery.
- **A baseline `git checkout <commit>` in a shared worktree leaves it detached, and later commits silently land off the branch.** Compare with `git stash`/`git show <rev>:<path>`/a throwaway `git worktree add` instead of checking out a bare commit in a tree others are committing to.
- **Alembic head revision id over 32 chars is a CI failure, not a style opinion** - `alembic_version.version_num` is `varchar(32)`; `tests/test_alembic_revision_ids.py` gates only the HEAD. Keep new ids short even when the filename stays long (`393_po_schedule_extractor_page_text.py` declares `revision = "393_extractor_page_text"`).
- **A dropdown over a large catalog must never be a capped static list - use a server-searched `SearchableSelect`.** `GET /master-data/products/select` defaults `DEFAULT_LIMIT = 100` against ~22,000 products; a picker that loads once and filters client-side answers "no results" for 99.5% of the catalog and looks like a search bug, not a paging one (hit twice: attachment linking, and a promotion picker fed `pageSize:1000`). Use async `SearchableSelect` with server `fetchOptions`, `paginated`, and a `selectedOption` fallback. Reference: `services/scmOptionsService.ts::searchProductOptions`.
- **A raw `text()` INSERT in a test skips every Python-side model default, and only CI notices.** `suppliers.is_active` (`default=True`, no server default) is filled by the ORM but not a raw insert; the dev DB (a prod copy) forgives it, CI's `create_all` schema rejects it. Seed through the model.
- **A pattern kill from one lane kills every lane** - `pkill -f next-server`/`uvicorn`/`worker.py` has no idea which worktree it is standing in and takes down every dev server on the machine with no error to the victim, just a dead port. **Never kill by pattern.** Kill by port (`lsof -ti :PORT | xargs kill`) or an explicit PID you started, and leave a port-probe watchdog running if a lane's server keeps dying under you.

## Extracted 2026-07-13, cross-repo and general gotchas

These were split out of `CLAUDE.md` in the first extraction. As binding as the rest.

- **Pydantic drops an unknown field name silently - a payload key typo becomes a missing value, not an error.** When two services exchange JSON the field names must match byte-for-byte; grep the RECEIVING schema, don't assume. A test asserting the wrong key freezes the bug in place until the assertion itself is corrected.
- **A URL-fragment credential collides with a component that appends a query string.** `/embed/ideas/{id}#token=<TOK>` plus a nav component appending `?ctx=...` folds the query INTO the fragment and corrupts the token. Fix: don't thread the token through in-page navigation URLs - persist it in an in-memory store on first load, read store-first on every route mount, keep nav paths plain.
- **A backgrounded uvicorn without `--reload` runs stale code** - a "fix didn't work" that's really "the fix never loaded". Restart the API (or start with `--reload`) after a backend edit before concluding the change is wrong; restarting the worker but not the API gives the SAME symptom, since each process has its own staleness window (`ps -p <pid> -o lstart=` vs `stat -f %Sm <file>`).
- **An unhandled backend 500 reads as a CORS error in the browser.** `CORSMiddleware` only attaches ACAO headers to responses it wraps; a request that raises past it (e.g. `ResponseValidationError`) produces a bare 500 with no CORS headers, so the browser reports a CORS error and hides the real one. Always read the backend log for the actual traceback before chasing a CORS config.
- **A reusable physical identifier needs the identity triple, not just the identifier** - "reusable once closed" is exactly where duplicates get in. A packing-list PDF re-uploaded after GRN fell through a container-only match (containers ARE reusable once received) and created a duplicate shipment. Fix: a RECEIVED shipment whose `(container, ETA, shipment_date)` triple equals the payload is a duplicate upload -> `409`; any date difference is a genuinely new shipment.
- **n8n writes integration errors into `response_payload`, but every user-facing surface reads the `error_code`/`error_message` COLUMNS.** The n8n error branch never sets those columns, so a real reason sits behind "View raw log" while the UI shows a bare "Integration failed". Fix is two-sided: the backend stamps the columns itself before raising (safe - n8n's follow-up POST can't clobber them via `exclude_unset=True`), and the FE falls back to `response_payload.error` when the column is NULL.
- **A new service-layer exception must be handled at EVERY route that calls the service, or a bare `except Exception` turns it into a 500 for one caller and a clean error for another.** `grep` every caller before shipping a new domain exception, and pin it with a test per caller.
- **Verifying "these failures are pre-existing" requires capturing the failure LIST, not the summary line.** `pytest -q | tail -3` keeps only the count; every later `grep FAILED` against it returns nothing, which reads as "no failures" when it means "no data". Capture `pytest -q | grep '^FAILED' | sort` on both sides and `comm -23` them.
- **The Bash tool's cwd persists across calls, so a `cd sub/dir && ...` silently invalidates later repo-root paths.** A follow-up `git status --porcelain -- path` or `git log -- path` after an unnoted `cd` prints empty output, indistinguishable from "clean/never committed". Anchor path-sensitive git commands with an explicit `cd <repo-root> &&`.
- **A manual probe against a stale dev DB can be unfalsifiable - it returns the miss value whether the code is right or hardcoded to fail.** Before reading a null/empty result as a verdict on the code, count the rows that satisfy every predicate in the query; if there are none, seed one (marker-scoped) so the guard has a case it CAN fail.
- **`git add` and `git commit` in separate tool calls are not atomic when anything else shares the repo** - a concurrent branch checkout between the two resets the index and "nothing added to commit" can mean the edits are still sitting in the working tree, not lost. Combine `add && commit` into one invocation; verify with `git rev-parse HEAD` against `origin/<branch>` rather than trusting push output.
- **An index created by raw `op.execute` in a migration is invisible in the model** - `__table_args__` under-reports what's actually indexed. Query `pg_indexes` or run `EXPLAIN` before concluding an index is missing; a model/DB drift here is a separate finding from whatever you were actually debugging.
- **A field written by an allowlist and read by a manual serializer must be in BOTH lists, and only a whole-set assertion catches the gap.** Naming fields one at a time is how this recurs (portal `pic` then `sales_type` hit the identical gap twice). Assert `set(_editable_fields(kind)) - set(_serialize_request_detail(row))` is empty, which prints the offending name on failure.
- **Every worktree shares one Redis, so an RQ job can be executed by a worker whose branch lacks the task function.** It goes to RQ's FAILED registry silently (`llen` reads 0), while the downstream row sits `pending` forever with no error surfaced. Diagnose with `FailedJobRegistry(queue=q).get_job_ids()` vs your own `worker_name`; `reg.requeue(jid)` fixes it. Real fix is per-worktree queue names.
- **Claude-managed background Bash tasks are reaped when the turn ends - a long-lived dev server must be detached.** Launch with `nohup ... > log 2>&1 < /dev/null & disown`, then verify with `lsof -ti :PORT` and an HTTP probe, not the task status.
- **A per-row query inside a serializer loop is an N+1 no test notices, and a column headed with an entity name must count DISTINCT entities, not join rows.** A promotions list issued one `COUNT` per row (12 rows -> 15 queries) AND separately over-counted "Products" via `count(promotion_products.id)` (a real cross-group extra row, not a duplicate to delete). Batch via `GROUP BY`; pin the query count with a `before_cursor_execute` listener (`<= 1`), never a wall-clock assertion.
- **A long unbroken token breaks layout two different ways, and both need the item to shrink FIRST.** In a fixed-layout table, `overflow-wrap: anywhere` (not `break-word`) is what lowers a cell's min-content width so `auto` sizing stays safe. In a CSS grid, an item defaults to `min-width: auto`, so `break-words` alone does nothing until the item also gets `min-w-0`. Verify by measurement (`scrollWidth` vs `clientWidth`/`getBoundingClientRect`), not by eye.
- **A consumer written against a shape the producer never emits fails silently and forever - the absent key just reads as the default.** An MCP presenter read a nested `certificate{}` key the backend never sent, so an expired-in-2016 certificate reported `"expired": false` with no error (the presenter's own tests used hand-written rows that DID contain the key). Two-sided shapes need a test on the PRODUCING side, not just the consumer.
- **An MCP list filter must be registered in TWO places, and forgetting the second one is an empty page, not an error.** A query param needs both the ToolSpec's `query_params` AND `TOOL_REQUIRED_NARROWING_FILTERS` in `server.py` - without the second, a call scoped only by that filter returns `{"data": []}` while the backend filter works fine, and the agent answers a silent wrong "no results" rather than erroring.
- **A list that opens with a default (opinionated) filter cannot be reconciled against another source, and the mismatch reads as data loss.** If a list's row count is something a human will compare externally (files on disk, a manifest), it must open UNFILTERED with the opinionated view as a filter-dropdown option, not the default.
- **Pushing to a branch after its PR has merged orphans the commit with no warning from any tool.** `gh pr view <n> --json state,mergedAt` before pushing follow-on work to an existing PR branch; if merged, cut a fresh branch from `origin/main` and cherry-pick, and verify with `git merge-base --is-ancestor <sha> origin/main` rather than trusting the push output.
- **A fixed `grid-cols-N` tab list collapses variable-length labels instead of overflowing visibly**, so it looks fine in every desktop screenshot until one more tab tips it over. Wrap by breakpoint (`grid-cols-2 sm:grid-cols-3 lg:grid-cols-5` + `h-auto`) and measure the tablist's `scrollWidth` vs `clientWidth` at 375px rather than eyeballing it.

## Retired

Kept for the record. Do NOT follow these - each is superseded by an entry above or a rule now
governed by `PRINCIPLES.md`/`CLAUDE.md`.

- **Playwright MCP can disconnect mid-session** - superseded by agent-browser verification (`CLAUDE.md` "Browser verification"); Playwright MCP is retired for verification, so its disconnect behaviour no longer applies.
- **sqlite pytest fixtures** - superseded by "Tests run on Postgres ONLY, NEVER sqlite" (`PRINCIPLES.md`); the sqlite-fixture workaround this described is now a banned approach, not a recipe.

## 89. A bootstrap assertion that names a rule dies the day the rule is retired (27 Aug 2026)

`scripts/bootstrap_env.py._fix_committed_v` asserted a hard-coded marker string as proof the newest `scm.committed_v` body had landed; migration 424 retired that leg on purpose, so every branch carrying 424 aborted CI in bootstrap before a single test ran, reading as test failures. Now asserts the current marker, but it is still a hard-coded substring - the same trap fires again next time the view is redefined. Prefer asserting on something the source-of-truth module exports.

## 90. CI's database is `bootstrap_env`, not the migrations - a view a migration redefines stays old on CI until bootstrap mirrors it (28 Aug 2026)

`scripts/bootstrap_env.py.create_views()` replays view DDL BY HAND and can lag a migration that used `CREATE OR REPLACE VIEW` - migration 420 redefined `scm.on_order_v` (LEFT JOIN) while bootstrap still built 337's body (INNER JOIN), so a drill-total test passed on the dev copy and failed only on CI. No CI check enforces the mirror. When a migration touches a view, update `bootstrap_env.create_views()` in the SAME commit, and reproduce a CI-only red from a from-zero database rather than trusting the dev copy.

## 91. The local Postgres runs `TimeZone = Asia/Seoul`, so a `now()` probe against a naive UTC timestamp lies by nine hours (28 Aug 2026)

`now()` is `timestamptz` converted through the session zone; a column that is `timestamp without time zone` holding UTC compared with `now()` shifts by the session's offset - locally hidden (Seoul), exposed on CI (UTC). Probe naive-UTC columns with `clock_timestamp() AT TIME ZONE 'UTC'`, never `now()`.

## 92. Under `from __future__ import annotations`, a pydantic field named after its own type resolves to itself (30 Aug 2026)

A field literally called `date` in a module with `from __future__ import annotations` makes every annotation a STRING resolved later against the module namespace - by then `date` is the field, not `datetime.date`, so `date: Optional[date]` reads as "must be None" and every dated value fails `response_model` validation while the service computed the right answer all along. Import compiles fine, which makes the tell misleading. Alias the type on the way in (`from datetime import date as DateType`) - the same trap waits on any field named `id`, `type` or `list` in a `__future__`-annotated schema module.

## 93. The venv is Python 3.14; CI is 3.12 - an f-string that reuses its own quote inside `{}` collects locally and is a SyntaxError on CI (30 Aug 2026)

`f"... {d["k"]}"` passes on 3.14 (nested same-quote expressions are allowed) and breaks `Validate backend imports` on 3.12 with `SyntaxError: f-string: unmatched '['`, taking an unrelated file down through the import while tests stay green. Use the other quote inside the braces (`{d['k']}`); compile changed files with a real 3.12 before pushing - a regex audit is not a parser.

## 94. A motion pass that samples mid-animation proves nothing about the end states (31 Aug 2026)

A sidebar collapse passed browser review because the tester sampled mid-collapse frames; both real defects lived in the AFTER states. Verify interactions as ROUND-TRIPS and measure final geometry (`getBoundingClientRect`, computed transform) in every end state - mid-animation screenshots are supporting evidence only, and a fix touching a mechanism re-verifies the mechanism's whole interaction, not just the symptom that was reported.

## 95. A per-migration test that asserts "X is the single head" fails on the very next migration (2 Sep 2026)

`test_453_is_the_single_head_of_the_whole_graph` asserted `heads == ['453_...']`; true the day it was written, false the moment a later migration chained onto 453. The property wanted is "the graph has one head and my migration is an ANCESTOR of it" - assert `len(heads) == 1` and walk `down_revision` from the head, never assert equality with a specific head id. The single-head fast gate in CI already covers the "one head" half.

## 96. A rule that only fires when a sibling rung FAILS gives two answers to one question (3 Sep 2026)

The SCM reorder ladder asked the asking bin's own site pool at step 0 but left OTHER site pools to a later spill step, reached only if earlier rungs had all failed - so the SAME rule answered two lines of one order two different ways depending on whether a sibling rung happened to succeed. State a rung's SCOPE up front and walk all of it there; a rung placed behind "if nothing else worked" is conditioned on facts unrelated to it, the tell that it is two rules wearing one name. The repair moved the whole chain into step 0 and deleted the spill, rather than adding a second trigger.
