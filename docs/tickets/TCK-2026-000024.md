# TCK-2026-000024 — Orders MCP: customer + product wildcard via embedding pre-resolve

> **Source ticket:** `TCK-2026-000024` (status: draft)
> **Priority:** medium · **Category:** feature
> **Dependencies:** TCK-2026-000026 (customer + transporter embedding) — required for customer/transporter fuzzy resolution. Product is already embedded (`embedding_worker.py:73–83`).

## Goal

Switch `crm_order_management_orders_list` / `crm_order_management_orders_by_product_list` from exact-match on `customer_query` / `product_query` to **embedding pre-resolve + ilike**, so partial / shortform / alias terms resolve.

Example: `customer_query="YOTU"` matches `YOTU BUILDER SDN BHD (PROJECT)` and any other `YOTU%` debtors; `product_query="WC101"` matches `SRTWC101` and `SRTWC101-RL`.

Return `matched_candidates` per dimension (customer, product, transporter) so the agent can echo to the user.

## Files to change

| File | Change |
|------|--------|
| `sorento_crm_mcp/sorento_crm_mcp/catalog.py` (lines 580, 624) | Update tool descriptions: "Fuzzy search via embedding + ilike. Accepts shortforms / fragments / aliases. Server returns `matched_candidates`." |
| `sorento_crm_backend/app/api/v1/order_management/orders.py` | Add `customer_query`, `product_query`, `transporter_query` handling: top-k embedding → expanded candidate codes → ilike on (`debtor_code`, `debtor_name`) for customer, (`product_code`, `product_name`, `product_description`) for product, (`transporter`) for transporter. |
| Response: include `matched_candidates: {customer:[], product:[], transporter:[]}` in payload so MCP can passthrough. |

## Step-by-step

1. Extract a shared helper in BE: `app/services/fuzzy_resolver.py` with:
   ```python
   def resolve_via_embedding_then_ilike(
       db, query: str, source_type: str, columns: list[Column], top_k: int = 10
   ) -> tuple[Filter, list[str]]: ...
   ```
   Returns SQL filter + list of matched canonical values.
2. Apply per dimension in the orders route.
3. Pass `matched_candidates` through to the response.
4. Update MCP catalog descriptions.

## Acceptance

- `customer_query="YOTU"` → response includes all YOTU* debtor rows AND `matched_candidates.customer` lists the canonical debtor codes/names.
- `product_query="WC101"` → response includes `SRTWC101*` rows AND `matched_candidates.product` echoes them.
- `transporter_query="<alias>"` works once TCK-2026-000026 is merged (transporter embedding live).
