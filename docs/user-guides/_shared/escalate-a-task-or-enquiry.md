# 0.4-Dashboard — Escalate a task or enquiry you can't handle

If you can't handle or resolve an enquiry/task in time (you need someone more senior, or it's beyond your scope), **escalate** it. Escalating moves it **up to the next tier** and reassigns it to the right person per the SLA policy, so it doesn't breach while it waits.

## From the dashboard (your pending tasks)

Open the [**Dashboard**](/) (home) → the **My pending tasks** widget → the **My Pending** tab → find the task → click **[Escalate](#guide_target=dashboard.sla-tasks.escalate)**.

- You'll be asked for a **reason** (why it needs escalating).
- On confirm: the task moves to the **next tier**, is **reassigned per policy**, and the **new assignee is notified**.
- **Escalate** isn't available once a task is already at the **top tier (3)** — there's nowhere higher to send it. At that point, handle it directly or use **Reassign** to hand it to a specific colleague.

## From inside a record (complaint / purchase request / stock inquiry)

When you're viewing the record itself, the same escalation is available on its **SLA controls** (the SLA stage banner / actions on the detail page). Open the record, find the SLA section, and use its **Escalate** action — it asks for a reason and bumps the SLA stage to the next tier the same way.

## When to escalate vs other actions

| Situation | Do this |
|-----------|---------|
| You can't handle it — needs a more senior tier | **Escalate** (with a reason) |
| You just need a specific colleague to take it | **Reassign** |
| You need more time but can still handle it | **Extend** the deadline |
| You're away and want someone to cover all your tasks | Set up **Coverage** |

## Notes

* Escalation always records your **reason** and notifies the new assignee, so the next person has context.
* If you're at the top tier and still stuck, escalate is disabled — reassign to the right person or resolve it.
