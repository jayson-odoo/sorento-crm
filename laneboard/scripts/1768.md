# Hand test: PR #1768, link every form to a project (lane FORMS-PROJECT)

Nothing here sends WhatsApp or email: use Save, never Update & Reply / Send.

## URL

crew test copy

## Setup

1. The test copy's DB needs the three new columns: run the `crew-migration` SQL posted on PR #1768.
2. Sign in as an admin. Pick two registered projects of your company: call them P1 and P2 (Project
   Sales > Projects). Note each one's code, e.g. `PRJ-000001`.
3. Pick one existing stock inquiry S that has a typed Project name and no project link.
4. For the portal steps: pick a portal contact C linked to your company (Users & Access > Contacts >
   C > Companies) and open "View as contact" for C.

## Steps

1. Sidebar > Project Sales Admin > Purchase Requests > Add. Fill the required fields, Registered project = P1, Save.
2. Open the saved purchase request.
3. Edit it, clear Project, Save, then open it again.
4. Edit it again, Project = P1, Save.
5. Sidebar > Procurement > Stock Inquiries > open S > Edit. Click the Project (optional) picker.
6. Pick P2 in that picker, Save.
7. Sidebar > Sales > Opportunities > Add: title "Hand test", a prospect name, a close date, Project = P2, Save.
8. On that opportunity: Edit, clear Project, Save.
9. Sidebar > Complaints > Complaints > open any complaint > Edit: Project = P1, Save.
10. Sidebar > Project Sales > Projects > open P1 > Forms tab.
11. Narrow the browser to phone width (375px) on the same Forms tab.
12. As contact C (portal): New Stock Inquiry, open the Project picker.
13. In that portal form pick P1, Save draft, then open the draft again.
14. Back as the admin: open P1 again and click the Orders tab, then the Forms tab.

## Expected

1. Saves with no error.
2. Detail shows Project `<P1 code> - <P1 title>` as a link; clicking it opens P1.
3. Detail shows "No project".
4. Detail shows the P1 link again (issue #1689 fixed: the staff pick is no longer dropped).
5. The picker's search box is already filled with S's typed Project name; nothing is linked yet.
6. Detail shows Project `<P2 code> - <P2 title>`; S's typed Project name is unchanged; the Audit Trail line reads `project_id: - → <P2 code> - <P2 title>`.
7. Opportunity detail shows Project `<P2 code> - <P2 title>`.
8. Opportunity detail shows "No project".
9. Complaint detail shows the P1 link.
10. Sections Complaints, Purchase requests, Sponsorship forms, Stock inquiries, Price tag requests,
    Sales opportunities. Complaints lists step 9's complaint; Purchase requests lists step 1's request;
    each row opens that form. Empty sections show a heading and a hint, no button.
11. Nothing on the page is cut off; each section's table scrolls sideways inside its own box.
12. The picker lists only projects of C's own companies (P1 and P2 among them), with the company name.
13. The draft reopens with Project `<P1 code> - <P1 title>`.
14. The tab row reads Overview, Stakeholders, Tasks, Quotations, Sample requests, Samples,
    Sponsorships, Forms, Orders, Activity, Documents (11 tabs; no separate POs, Delivery schedules or
    Sales orders tab). Orders shows P1's purchase orders and sales orders (or their empty states); Forms
    shows the same sections as step 10.
