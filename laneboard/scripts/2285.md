# Hand test: PR #2285 SCHEDULED-TASKS-GRID (Town job on Scheduled Tasks, one-line grid)

The Town snapshot job now lives on System Management > Scheduled Tasks like every other cron job, with its
last run, last status, last error, next run, Enabled switch and Run now. The grid sorts and filters on the
server and keeps every row on one line.

## URL
crew test copy

## Setup
1. Sign in as a superadmin.
2. The test copy's database has the `town_snapshot` row (migration town_0002_scheduled_task, or the
   crew-migration SQL on the PR).
3. The backend runs with the scheduler on (ENABLE_SCHEDULER=1 on the API or worker), and Redis is up.

## Steps
1. From the sidebar open System Management > Scheduled Tasks.
2. Type "town" in the search box.
3. Read the "Sorento town snapshot" row.
4. Clear the search. Hover the Last error cell of any row that has an error.
5. Click the Frequency header, choose ascending; then descending.
6. Click each other header in turn (Name, Enabled, Last status, Last run, Next run, Last error) and sort.
7. Open Filters; Last status: tick Failed and Never run.
8. Clear that filter; Enabled: tick Disabled; then tick Enabled as well.
9. Open the column chooser and turn on Key.
10. Narrow the window to 375px wide and look at the grid; widen back to 1280px.
11. Click the "Sorento town snapshot" row.
12. Click Run now, wait 10 seconds, refresh.
13. Turn the Enabled switch off, save, go back to the list; then turn it back on.

## Expected
- Step 3: one line reading Sorento town snapshot | Every 3 mins | Enabled | a status pill | Last run and Next run as
  dd/mm/yyyy, h:mm am/pm (Malaysia time) | Last error "-" or the error text. Next run is about 3 minutes after
  Last run.
- Step 4: the cell shows a clipped single line; the tooltip shows the full error.
- Every row in every step is ONE line high; no description line under the name.
- Step 5: ascending puts seconds tasks first, days tasks last; descending reverses it.
- Step 6: each header reorders the list (empty values at the bottom).
- Step 7: only tasks whose last status is Failed or that never ran.
- Step 8: Disabled only, then all tasks.
- Step 9: a Key column appears (e.g. town_snapshot).
- Step 10: the grid scrolls sideways inside its card at 375px; nothing overlaps; rows stay one line.
- Step 11: the detail page for Sorento town snapshot with its description, Enabled switch, Run now and run log.
- Step 12: a new run row in the run log. Between 07:00 and 22:05 Malaysia time it reads Success with
  summary companies/built/failed 0, or Failed with "Town snapshot failed for N of M companies: <company
  name>: <error>" (also shown as Last error on the list). Outside those hours: Success, "outside 07:00-22:05
  Malaysia time".
- Step 13: the list shows Disabled for the row, then Enabled again; no Town runs are logged while disabled.
