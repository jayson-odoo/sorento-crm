# Hand test: PR #2172 PRICETAG-COMBO-RENDER (price tags render every combo shape)

A combo names its own groups, fixed parts and upgrades. A tag template points at positions in the
combo (main product, fixed part n, pick k of group g, upgrade n) and its needs are read from its
layers. The request line shows a multi-select for a group the template needs two or more from, a
combo line prints the combo's stored price or nothing (never a sum of the parts), a discontinued
part is marked and blocks Approve, and the designer names positions from the combo it previews.

## URL
crew test copy

## Setup
- From the test copy's backend folder, on the shared dev DB, run once (safe to repeat; it refuses
  any database whose name has no `dev` or `ci` token):
  `venv/bin/python scripts/seed_pricetag_combo_shapes_dev.py --confirm-db sorento_prod_1020` (dry run),
  then `venv/bin/python scripts/seed_pricetag_combo_shapes_dev.py --apply --confirm-db sorento_prod_1020`.
  The shared dev copy is named `sorento_prod_1020`, so the name check needs `--confirm-db` with the
  exact database name (the script prints host and database first and refuses any other value).
  (add `--company SRT` only if the default is not SRT). It ensures the combos "Basin + tap",
  "Basin + tap colour", "Sink + taps with top-up" (and "Basin + tap colour (discontinued option)"
  when a discontinued SRTWT5831-BL exists), creates the four "Combo 105 x 148: ..." templates and
  links every one that fits to those combos and to the existing SRTKS7061 and SRTBF11829 combos.
- Signed in as a salesperson who can use the Price Tag Request form (customer portal or CRM), with
  Dealer Kit > Tag Templates open to a marketing user for the designer steps, window about 1280 px.
- Leave the combos' list and selling prices empty except "Sink + taps with top-up" (selling 849).

## Steps
1. New Price Tag Request, add SRTKS7061, choose the package "Sink + taps with top-up".
2. In the Template select pick "Combo 105 x 148: 2 picks".
3. In the Kitchen tap row open the select, pick one tap, look at the hint under the row, then pick
   a second tap (remaining taps grey out) and a third attempt.
4. Switch the Template to "Combo 105 x 148: 5 picks and an upgrade" and look at the options.
5. Back to the 2-pick template, pick SRTKT71SS in the upgrade row, set the line to SP.
6. Add SRTWB1419-BL, package "Basin + tap colour", template "Combo 105 x 148: 2 picks", pick both
   colours.
7. Save Draft. Start a SECOND New Price Tag Request (a product appears once per request, so the
   same basin cannot be added twice), add SRTWB1419-BL, package "Basin + tap", and read the
   Template select and the line.
8. Add SRTBF11829, template "Combo 105 x 148: 2 fixed parts", then look at its fixed parts.
9. On this second request, set the "Basin + tap" line (line 1, no stored selling price) to SP, leave the price
   box empty, and read the reason beside Approve. Type a price, read it again, clear it.
10. Set that line to LP, with no combo list price, and read the List price cell and the reason.
11. Click Escalate on such a line and send a note.
12. Reopen the FIRST request's draft and, on the SRTKS7061 line with the 2-pick template, pick
    SRTKT1871SS then SRTKT1862SS (in that order). Save Draft, close the page and reopen the draft.
13. In Dealer Kit > Tag Templates open "Combo 105 x 148: 2 picks". In the Preview combo bar pick
    "Basin + tap colour", select the layer that reads pick 2, and open the Product select. Then
    pick "Sink + taps with top-up" and look at the Layers panel names and the list price.

## Expected
- Step 2: the Template description reads "105 x 148 mm. Needs 2 from Kitchen tap"; the Kitchen
  tap row is a multi-select with the placeholder "Pick 2" and no "Select all".
- Step 3: after one pick the hint reads "Kitchen tap: pick 1 more." and it disappears after the
  second; every other tap is disabled once two are chosen; chips show in pick order.
- Step 4: "Combo 105 x 148: 5 picks and an upgrade" is not offered for a three-tap package (or is
  disabled with "Needs 5 from choice group 1; Kitchen tap has N", N being the number of taps in
  the package, in the combo picker on the product page); the other starters stay.
- Step 5: Approve is on for this line; with SRTKT71SS picked the tag prints RM 999 (the combo's
  849 plus the 150 top-up), never the sum of the parts.
- Step 6: both colours are chips; the tag shows two picks, each with its own picture and code.
- Step 7: "Combo 105 x 148: 1 fixed part" is offered and the free item is a template picture.
- Step 8: a fixed part whose product is discontinued shows the badge "Discontinued" and Approve
  is off with "<code> is discontinued. Escalate it to marketing." A discontinued option in the
  pick select is listed disabled with "Discontinued" and a pick already held gives "<code> is
  discontinued. Pick another or escalate it to marketing."
- Step 9: with SP, no typed price and no stored selling price the reason beside Approve reads
  "No combo selling price for line 1. Type the selling price or escalate it to marketing." and
  Approve is off; once a price is typed Approve is on; cleared, it is off again.
- Step 10: List price shows "-" and the reason reads "No combo list price for line 1. Escalate it
  to marketing." Approve is off. Approving by any other route is refused by the server with the
  combo price message.
- Step 11: Escalate is still available and sends the request to marketing.
- Step 12: the draft reopens with ONE Kitchen tap multi-select row holding SRTKT1871SS then
  SRTKT1862SS, and the eye-icon preview shows the two taps in that order.
- Step 13: the Product select lists "Main product", "Basin + tap colour"'s own positions grouped
  as "Tap colour, pick 1" and "Tap colour, pick 2" with the product codes, then (for the sink
  combo) "Kitchen tap, pick 1" up to one entry per tap in the package, and "Upgrade 1". The Layers panel suffix uses the same names,
  and the list price slot is empty when the previewed combo has no list price (not the host's).
