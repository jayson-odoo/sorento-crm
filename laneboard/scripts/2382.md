# PR 2382 hand test: search chips on the document lists (slice 2)

## URL
crew test copy

## Setup
- No migration (to be confirmed by the query-cost check; if a list gets indexes, the crew-migration block on PR 2382 comes first). Sign in as admin.
- Before starting, note from each list two document numbers on page 1 (call them A and B) and the customer or supplier name of a third row (call it C). Any real values from the copy work; nothing is entered into the system.

## Steps
1. From `/`, open Delivery Orders in the sidebar.
2. Click the search box, type A and press Enter, type B and press Enter, type C and press Enter.
3. Click a row (on a cell, not on the number link), use the record's next arrow once, then go Back to the list.
4. Press the browser's Refresh (F5).
5. Click a column header once to sort.
6. Click the box's x (Clear search).
7. Repeat steps 2 to 6 on Purchase Orders, Consignments, Order Inquiries and Proforma Invoices (each from the sidebar).
8. On Delivery Orders, with three chips, tick two rows and use Export.
9. Shrink the browser to phone width (375px) and repeat step 2 on Purchase Orders.

## Expected
- Step 2: three chips in the box (C is ONE chip, spaces kept); the list shows A, B and every row of C; the third chip may show as "+1" when the box is narrow.
- Step 3: the next arrow walks only the chip result; Back returns to the list with the same three chips and the same rows.
- Step 4: after the refresh the three chips and the rows are still there.
- Step 5: the same rows, sorted; page 2 (if any) continues the order.
- Step 6: chips cleared; the full list returns.
- Step 7: the same results on every list (Proforma Invoices has no sortable columns: skip step 5 there).
- Step 8: the file holds exactly the two ticked rows.
- Step 9: the box fills the row; chips and "+N" fit with no sideways scrolling.
