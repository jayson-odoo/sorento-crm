# Hand test #1390 (CUSTOMER-CODE-IDENTITY, re-scoped: SO-level customer name)

## URL
crew test copy

## Setup

1. Sign in as an admin (someone who can open Order Management > Customers and Supply Chain > Sales Orders).
2. The test copy database has the additive migration applied (`sales_orders.debtor_name`; the crew-migration comment on the PR carries the SQL).
3. Have the external API key of the test copy (`EXTERNAL_API_KEY` in the backend `.env`) and Sorento's company code (`companyCode` in the ingest payloads, the value the ESB sends).
4. Pick any existing customer code, for example `300-1001`, and note the name the Customers page shows for it.

## Steps

1. Push a sales order for that code under a changed debtor name (replace the placeholders):
   ```
   curl -s -X POST http://<test copy backend>/api/v1/external/ingest/sales_orders \
     -H "X-API-Key: <EXTERNAL_API_KEY>" -H "Content-Type: application/json" \
     -d '{"companyCode":"<companyCode>","records":[{"source_ref":"HT1390-SO-1","so_number":"HT1390-SO-1","status":"open","customer_code":"300-1001","customer_name":"MODERNMED SDN BHD","lines":[{"source_ref":"HT1390-SOL-1","product_code":"<any live product code>","qty_ordered":2}]}]}'
   ```
   Read `records[0].outcome` in the reply.
2. From the sidebar open Supply Chain > Sales Orders and search `HT1390-SO-1`. Read the Customer column. Open the order and read the customer name on the detail.
3. On the same list, search `MODERNMED`. Count the rows.
4. From the sidebar open Order Management > Customers and search `300-1001`. Read the customer name.
5. Push the same order again with `"customer_name":"1 LIVING DEPOT SDN BHD"` (same `source_ref`). Search `HT1390-SO-1` on Supply Chain > Sales Orders and read the Customer column.
6. Push the same order again with NO `customer_name` key. Search `HT1390-SO-1` again and read the Customer column.
7. Open Supply Chain > Reorder planning, open any completed plan, open the demand popover of a product that `HT1390-SO-1`'s line names (or run a small plan over that product first). Read the customer shown for that order's demand.
8. Ask the WhatsApp bot "outstanding SO for 300-1001" from a contact allowed to see it, and read the customer printed for `HT1390-SO-1`.

## Expected

1. `outcome` is `created`.
2. The Customer column and the detail both read `MODERNMED SDN BHD` (the name the order was issued under), not the master name from Setup step 4.
3. At least one row, `HT1390-SO-1` among them: the search matches the order's own name.
4. The master name is unchanged from Setup step 4: a document never renames the customer.
5. The Customer column reads `1 LIVING DEPOT SDN BHD`: the order carries its own latest name.
6. Still `1 LIVING DEPOT SDN BHD`: a push without a name leaves the stored one alone.
7. The demand row for `HT1390-SO-1` prints `1 LIVING DEPOT SDN BHD`; orders pushed before this change still print the master name.
8. The bot's row for `HT1390-SO-1` prints `1 LIVING DEPOT SDN BHD`.
