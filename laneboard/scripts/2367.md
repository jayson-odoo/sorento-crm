# PR 2367 hand test: list search turns Enter into chips (Sales Orders)

## URL
crew test copy

## Setup
- The test copy needs the search indexes: the `crew-migration:` SQL block on PR 2367 (index builds only, no data change). Sign in as admin.
- Pick from the Sales Orders list, before starting, and note them down: two SO numbers from page 1 (call them SO-A and SO-B), and the customer name of a third order on page 2 (call it CUST-C). Any real values from the copy work; nothing is entered into the system.

## Steps
1. From `/`, open Sales Orders in the sidebar (Project Sales Admin > Sales Orders).
2. Click the search box, type SO-A and press Enter.
3. Type SO-B and press Enter.
4. Type CUST-C (the customer name, with its spaces) and press Enter.
5. Click the column header "Document date" once, then go to page 2 if there is one.
6. Click any row to open the order, then use the record's next arrow once, then click Back to the list.
7. Press the browser's Refresh (F5).
8. Click the x on the SO-B chip.
9. Press Backspace twice in the empty search text.
10. Copy these three values separated by new lines from a text editor: SO-A, SO-B and one SO number that does not exist (e.g. `SO000000`), and paste them into the empty box.
11. Clear the box with its x. In a text editor write SO-A and SO-B on one line with a space between, copy that line and paste it into the box.
12. Type part of a customer name without pressing Enter and wait one second.
13. Click the box's x (Clear search).
14. Add 8 SO numbers (Enter after each), then click outside the box.
15. Click the box again.
16. Shrink the browser to phone width (375px) and repeat steps 2-4.
17. Tick two rows and use Export.
18. Clear the box. From an Excel column or text editor, copy 30 SO numbers (one per line) and paste them into the box.

## Expected
- Step 2: SO-A shows as a chip inside the box; the text part is empty; the list shows only SO-A.
- Step 3: two chips; the list shows SO-A and SO-B.
- Step 4: three chips (CUST-C is ONE chip, spaces kept); the list shows SO-A, SO-B and every order of CUST-C.
- Step 5: the rows stay the same set, sorted by document date; page 2 continues that order (with only 3 chips there may be no page 2: then add a broader chip such as the first 4 characters of an SO number).
- Step 6: the next arrow walks the same filtered list; Back returns to the list with the same three chips and the same page.
- Step 7: after the refresh the three chips and the result are still there (the address bar holds them).
- Step 8: SO-B is gone from the chips and the list.
- Step 9: the two remaining chips are removed one by one; the full list returns.
- Step 10: three chips appear; the list shows SO-A and SO-B; the non-existent number just adds nothing.
- Step 11: two chips, SO-A and SO-B.
- Step 12: without Enter, the typed text searches live as one more value: the list shows the chip results plus the orders matching the typed text.
- Step 13: all chips and the text are cleared; the full list returns.
- Step 14: the box shows one line with the first chips and a "+N" chip; nothing wraps.
- Step 15: the box opens downward over the rows showing all 8 chips, with "8 values" and "Clear" underneath; Esc folds it back.
- Step 16: the box fills the row; chips and "+N" fit with no sideways scrolling.
- Step 17: the file holds exactly the ticked rows from the chip result.
- Step 18: 30 chips (one line with "+N"); the list shows those orders within about a second, with no spinner hanging.
