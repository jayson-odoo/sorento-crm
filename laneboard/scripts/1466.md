# Hand test #1466 (CHAT-SLOW-MISS)

## URL
crew test copy

## Setup

1. Sign in as an admin who can open System Management > Chatbot Console.
2. Use the dealer contact from the 4 Oct console run that showed "internal server error". Any contact allowed to check stock works, as long as SRTWC286 and SRT5764 exist on the test copy and SRTWC6022 does not.
3. Keep the backend log of the test copy open (the terminal running uvicorn), so step 7 can be checked.

## Steps

1. From the sidebar open System > Messaging > Chatbot Console and pick the contact.
2. Send `check stock srtwc286`. Read the reply.
3. Send `srtwc286 , srtwc6022  srt5764  stock`. Wait for the reply without refreshing, however long it takes.
4. Click `trace` under that reply and read the `routed` stage duration.
5. Send `check stock srtwc6022`. Read the reply.
6. Send `srtwc286 , srtwc6022  srt5764  stock` once more and read the `routed` stage duration in its trace.
7. In the backend log, search for `retrying without it`.

## Expected

1. The console opens with the contact selected.
2. A normal stock reply for SRTWC286 (code, name, location, quantity), with no error toast.
3. A reply arrives: stock for SRT5764 and SRTWC286, then `I could not find srtwc6022.` (or a "did you mean" offer for it). There is no "Internal Server Error" toast or page, even if the turn takes longer than 30 seconds.
4. The `routed` stage is well under the 25 to 34 s seen on 4 Oct. The repeated lookups of the missing code are gone; on the crew sandbox it fell from 2.9 s to 1.8 s.
5. `Couldn't find "srtwc6022" (product). Did you mean:` followed by the nearest codes (SRTWC6028 / SRTWC604 style neighbours where they exist), then the escalate offer.
6. About the same `routed` time as step 4. The second ask costs no more than the first.
7. No `openai: model rejected 'max_tokens', retrying without it` lines from steps 2 to 6. Before this PR, every LLM call logged one.
