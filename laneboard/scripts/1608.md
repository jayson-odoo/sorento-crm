# Crew verification: PR #1608 SCOPE-FRAMES (embedding scope: frames, deleted sources, certificate codes)

Backend-only lane: no screen changes. Crew runs every step on the test copy; the owner runs no
commands and reads the results.

## URL

crew test copy

## Setup

1. Test copy of this PR's head (the sha in the latest crew-status comment), backend from
   `sorento_crm_backend/`, migrated to head so `sframes_0001_frame_company` has run. Crew already
   ran it on the dev DB on 13 Oct: it logged `stamped company_id on 9 conversation_frame embedding
   document(s)` and `queued 108 certificate embedding rebuild(s)`.
2. `BE` = the copy's backend URL. `KEY` = the copy's `EXTERNAL_API_KEY` (the legacy shared key: the
   only key that gets a contact company scope; any other integration key reads 0 rows when scoped).
3. The copy needs `OPENAI_API_KEY`: the RAG search embeds the query text. Without it steps 4 to 6
   answer 503 and are skipped.
4. `psql "$DATABASE_URL"` reaches the copy's database. Every SQL below is read-only.

## Steps

1. Run `psql "$DATABASE_URL" -Atc "SELECT count(*), count(*) FILTER (WHERE company_id IS NOT NULL), (SELECT count(*) FROM embedding_chunks c JOIN embedding_documents d ON d.id = c.document_id WHERE c.source_type='conversation_frame' AND c.is_current AND d.is_active) FROM embedding_documents WHERE source_type='conversation_frame'"`.
2. Run `psql "$DATABASE_URL" -Atc "SELECT count(*) FROM embedding_chunks c JOIN embedding_documents d ON d.id = c.document_id WHERE d.source_type='conversation_frame' AND c.company_id IS DISTINCT FROM d.company_id"`.
3. Pick a contact in exactly one company: run `psql "$DATABASE_URL" -Atc "SELECT rc.respond_io_id || ' ' || w.space_id FROM respond_contacts rc JOIN respond_workspaces w ON w.id = rc.workspace_id JOIN respond_contact_companies rcc ON rcc.respond_contact_id = rc.id WHERE rc.respond_io_id IS NOT NULL GROUP BY rc.respond_io_id, w.space_id HAVING count(*) = 1 LIMIT 1"` and keep the two values as CID and SID.
4. Run `curl -s -X POST "$BE/api/v1/external/rag/search?contact_id=$CID&space_id=$SID" -H "X-API-Key: $KEY" -H 'Content-Type: application/json' -d '{"query":"what did I ask about last time","source_type":"conversation_frame","top_k":10}' | python3 -c "import json,sys; print(len(json.load(sys.stdin)['data']))"`.
5. Run the same curl with `"source_type"` removed from the body, piped through `python3 -c "import json,sys; print(sorted({r['source_type'] for r in json.load(sys.stdin)['data']}))"`.
6. Run the curl from step 4 without the `?contact_id=...&space_id=...` query string, piped as in step 4.
7. Run `psql "$DATABASE_URL" -Atc "SELECT (SELECT count(DISTINCT q.source_id) FROM embedding_queue q WHERE q.source_type='certificate' AND q.event_type='embedding.rebuild_requested'), (SELECT count(*) FROM embedding_documents WHERE source_type='certificate'), (SELECT count(*) FROM embedding_documents d WHERE d.source_type='certificate' AND NOT EXISTS (SELECT 1 FROM certificates c WHERE c.id::text = d.source_id))"`.
8. Run `venv/bin/python scripts/purge_orphan_embeddings.py` (dry run; deletes nothing).
9. Run step 8 again.
10. Run `venv/bin/python scripts/purge_orphan_embeddings.py --apply` (no `--expect`).
11. Run the lane's tests ONLY against a `*_ci` test database, never the shared dev DB:
    `SORENTO_ENV_FILE=<an env file whose DATABASE_URL ends in _ci> venv/bin/python -m pytest -q tests/test_embedding_scope_frames.py`.
    Optional guard check: run it once with the copy's dev env.

## Expected

1. Three numbers `N|9|C` on the dev DB as of 13 Oct: N is every frame document, 9 of them carry a
   company (the 9 the migration stamped; a frame whose contact is in several companies or none
   stays without one, by design), and C is the frame chunks a search can return.
2. `0`: every frame chunk carries the same company as its document.
3. One line, a Respond.io id and a space id. If it prints nothing, skip steps 4 and 5.
4. `0`: a contact-scoped search returns no conversation frame at all, not even one of its own
   company (crew ruling (a): a frame is one contact's private conversation).
5. A list of source types that does NOT contain `'conversation_frame'`.
6. `min(C, 10)` with C from step 1 (the search has no similarity floor, so it returns that many):
   staff and unscoped key calls still see frames.
7. `108|157|49` on the dev DB as of 13 Oct: 108 certificates queued for a rebuild, 157 certificate
   documents in all, and 49 of those are orphans whose certificate row is gone. 108 + 49 = 157: the
   migration queues only certificates that still exist, and the orphans are left to step 8. If the
   copy's worker and scheduler run, rebuilt rows leave `pending`, but the first number stays 108.
8. First line `database: <the copy's database name>`, then lines of `<source_type>: <count>`,
   then `would delete: <total> document(s)`. On the dev DB as of
   13 Oct (crew run): `certificate: 49` (the step 7 orphans), `order: 36517`, `order_line: 40290`
   among the lines, total `102633`. Intended: every one is the embedding of a row that no longer
   exists (orders and order lines are replaced by imports and have no delete listener), so it is
   stale; it is NOT deleted here. Deleting is the owner's prod release step (PR body).
9. Exactly the same output as step 8: the dry run deleted nothing.
10. Exit code 2, `database: <name>` then `refused: --expect does not match the orphan count found
    now; run the dry run and pass its total`. Nothing is deleted, and the refusal does not print
    the total (only a dry run shows it).
11. On a `*_ci` database: `16 passed`. With the dev env: `13 passed, 3 skipped`, the 3 skips
    reading `refused: <dev db name> is not a *_ci test database; this test runs a global sweep`
    (the purge, purge-script and backfill tests never touch the dev DB).
