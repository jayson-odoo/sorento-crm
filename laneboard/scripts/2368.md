# PR 2368 hand test: chatbot replies faster, same answers (CHATBOT-SPEED), BEFORE / AFTER card

**In one line: each reply comes back about 0.3-0.6 s faster, and the answers are identical.**
The plan v2 Phase 0 finish line is 0.4 s; this PR's measured median saving is 0.4 s on the part it changes
(the work before the parser) and 0.3-0.6 s on the whole reply. No screen changes; only the time goes down.

Numbers below are already measured (no new model call needed): crew pass 6845071213 and data check 6845204063,
3 rounds per side, warm-up "hi" left out, median per question.
- BEFORE = main `4dfe5b2f` (this PR's base).
- AFTER = this PR's code head `356c2378` (the branch head `6f75440a` adds a plan note only, no code).

## The card: 5 questions, before vs after

Ask each as: **a staff contact** (Chatbot Console > Contact: pick one staff contact, the same one for both runs).

| # | Ask (type exactly) | Answer | Whole reply, BEFORE (s) | Whole reply, AFTER (s) | Saved (s) | Before the parser, BEFORE -> AFTER (s) |
|---|---|---|---|---|---|---|

| 2 | `please share new mocha promotion` | identical before and after | 5.6 | 5.0 | 0.6 | 1.8 -> 1.4 |

Repeat pass on these 5 questions (crew pass 6849046121, production prompt v72, 3 rounds per side): median whole reply
6.10 -> 4.99 s (1.11 s saved), before the parser 1.78 -> 1.33 s, products, codes and quantities identical in 15/15 pairs.
Model noise is about +/- 0.5 s per run, so the promise stays "about 0.3-0.6 s"; a walk can show more.

All numbers are on the **production parser prompt (v72)**. The Console's Prompt version picker defaults to an older
full prompt (v61) that has no span step before the parser, so on v61 this PR has nothing to speed up and a walk shows
no saving. Setup and step 2 below clear the picker so the Console runs the production prompt.

How to read it:
- "Whole reply" is what the owner feels: send to reply. It includes two AI model calls (about 4.6 s of the 5.3 s),
  which this PR does not touch and which vary by about +/- 0.5 s run to run. So one question can come out even (row 5).
- "Before the parser" is the part this PR speeds up: it drops on every one of the 5 questions (0.3-0.5 s each).
- Median saving: 0.3 s (difference of the two medians) to 0.6 s (median of the per-question savings).
- Not visible in the Console: on real WhatsApp turns the respond.io check and the reply send also reuse one open
  connection, so real turns save a little more after release.

## Setup
- One crew test copy and one database for both runs, so only the code differs:
  - BEFORE: a backend on main `4dfe5b2f` that crew runs for the owner (same dev DB, AI settings and key, own Redis
    index, stopped right after), as in crew passes 6845071213 and 6849046121.
  - AFTER: the copy's own backend on `356c2378`.
  - The frontend can stay on the PR head for both runs; this PR changes no frontend file.
- No worker needed: Console turns run in the API process. AI settings as they are; nothing is changed.
- Sign in as admin. In the Console's Contact picker choose one staff contact and keep it for both runs. Crew names
  the exact contact on the test copy (several staff contacts share a first name; pick the one crew names).
- Prompt version: clear the picker (the x) so it reads "Live (production label)". That runs the production prompt v72,
  the one the card was measured on. Do not leave it on the default "v61 · full".
- The trace drawer shows each stage's time, not the whole reply's time. The whole-reply column comes from crew's
  table at the end (step 13), read from the stored turns (no model call).
- Pace: send each question as soon as the previous reply arrives. Open the traces only after the last question.
- Spend: 12 turns x 2 model calls on the copy's own key, about US$0.05-0.10. Optional: the card above is already measured.

## Steps
1. BEFORE: with the backend on `4dfe5b2f`, from `/` open System > Messaging > Chatbot Console in the sidebar.
2. Choose the staff contact crew names in Contact, and clear Prompt version so it reads "Live (production label)".
3. Send `hi` and wait for the reply (warm-up, not counted).
4. Send `stock SRTWC8517`.
5. Send `please share new mocha promotion`.
6. Send `srt a3 flyer`.
7. Send `matt black tap price`.
8. Send `any basin 600mm in stock?`.
9. Under each of the 5 replies click **trace**; in Stages note the ms next to **understood**; press Escape.
10. AFTER: crew points the Console at the backend on `356c2378`. Reload the Console page, choose the same staff contact and clear Prompt version again.
11. Repeat steps 3 to 9.
12. Put each BEFORE reply next to its AFTER reply.
13. Crew prints the before/after table from the stored turns and pastes it in the thread.

## Expected
- Every question gets a reply on both sides; nothing hangs, nothing errors.
- Step 12: the same answer on all 5 (same products, codes, quantities); only model wording may vary, and it varies
  the same way on both sides.
- Step 9 vs step 11: the **understood** stage is lower AFTER on most questions (about 0.4-0.5 s at the median;
  it also holds the parser's own model call, so one question can come out even).
- Step 13: AFTER whole reply near the card's AFTER column (about 4.6-6.4 s), BEFORE near the BEFORE column (about
  5.4-6.8 s); median saving across the 5 about 0.3-0.6 s or more; "Before the parser" lower on at least 4 of 5.
  Crew runs, read-only, from `sorento_crm_backend/`:
  `SORENTO_ENV_FILE=<copy env> venv/bin/python -m scripts.chatbot_eval.speed_table --minutes <since step 1>`.
  The table counts any turn without a span step as "old" (`speed_table.py:24-30`), so it is only right when every
  turn in the window ran v72 (Prompt version cleared): leave out any turn sent on v61 by narrowing `--minutes`.
