# Hand test #1436 (PICKER-NO-CAP)

Every chatbot turn below runs in the Chatbot Console, which is a dry run (`is_test`): nothing is
sent over WhatsApp or email. Do not use Respond Outbox, Email Outbox or any "send" button.

## URL

crew test copy

## Setup

1. Apply the crew-migration on the PR (moves every entity kind's Roster cap still at 10 to 50):
   `ALTER TABLE chatbot_entity_kinds ALTER COLUMN roster_cap SET DEFAULT 50;`
   `UPDATE chatbot_entity_kinds SET roster_cap = 50 WHERE roster_cap = 10;`
2. On the shared dev DB, find a product code prefix B that more than 10 (and at most 20) chat
   products start with:
   `SELECT g.b, g.n FROM (SELECT split_part(upper(replace(p.product_code, ' ', '')), '-', 1) AS b, count(*) AS n FROM products p WHERE p.is_searchable IS NOT FALSE AND p.category_id NOT IN (SELECT id FROM product_categories WHERE is_searchable IS FALSE) GROUP BY 1) g WHERE g.n BETWEEN 11 AND 20 AND NOT EXISTS (SELECT 1 FROM products e WHERE upper(replace(e.product_code, ' ', '')) = g.b) ORDER BY g.n DESC LIMIT 5;`
   Take the first row's `b` as B (B is not itself a product code, so no exact match skips the list).
3. List the products the picker should show for B (call the row count M, between 11 and 20):
   `SELECT product_code FROM products p WHERE upper(replace(p.product_code, ' ', '')) LIKE 'B%' AND p.is_searchable IS NOT FALSE AND p.category_id NOT IN (SELECT id FROM product_categories WHERE is_searchable IS FALSE) ORDER BY product_code, id;`
   (replace B in the query). If M is over 20, go back to step 2 and take the next row.
4. Pick contact N: a Respond contact with the full incoming view (not availability only), the same
   kind of contact used in the #1329 hand test.

## Steps

1. Sidebar > System Management > Chatbot entity kinds. Open Product, click Edit, read the Roster cap
   field, close without saving. Do the same for Customer and Inbound shipment.
2. Click Add (new entity kind). Read the Roster cap field, then close the modal without saving.
3. Sidebar > Chatbot Console. Contact = N. Send "incoming B".
4. Count the numbered lines in the reply.
5. Reply with the number M (the last line's number).

## Expected

1. Step 1: Roster cap reads 50 for Product and Customer. Inbound shipment keeps the 20 you set
   earlier: the migration only moves rows still at 10. Inbound shipment does not affect the
   incoming picker; that picker reads Product.
2. Step 2: the new kind's Roster cap field reads 50.
3. Step 3: the reply says the search needs to be more specific and lists M numbered lines, `1.` to
   `M.`, one per code from setup step 3 (a code both companies hold may show its company beside it),
   each ending in " - has incoming" or " - no incoming". There is no cut at 10, no "(+N more)" and
   no "and N others" line.
4. Step 4: exactly M numbered lines (more than 10).
5. Step 5: the bot answers the incoming question for the code on line M of the step 3 reply, not
   "I could not find" and not the same list again.
