# Hand test: PR #2221 SPLIT-SHEET-LOCATION (an SO line location change is detected like a qty / date change)

When AutoCount (or a Project Sales Admin Sales Order edit) moves an SO line to another location, the board shows the
change, CS re-confirms, and the purchasing email of that Confirm says `NEW LOCATION (was <old>)`. As QTY | NEW QTY
and DELIVERY | NEW DATE do, the Confirm's Review split, the email table and its Excel attachment print LOCATION = the
old location and NEW LOCATION = the new one, right after it, filled only on a moved line. A line with no pending
move reads its AutoCount location, as the board does. The Order Inquiry rows and links stay as they are (no cancel,
no fresh order). Lines moved before this ships are not flagged (no backfill).

crew test copy

## Setup
1. Sign in with your own login.
2. Part A uses SO389394 line 272: a line whose planned location differs from its AutoCount location from before
   this lane (the no-backfill example; SO429664 is not on the dev copy).
3. Part B uses SO427856 line 64: AutoCount location BRW-IB, Confirmed as Buy 20. Note its Order Inquiry row (qty,
   state) before you start. Pick a sibling location in the same pool to move it to (for example BRW-BB).

## Steps
1. Sidebar: Supply Chain > Project Demand (Fulfilment Planning), filter SO389394.
2. Note the Location of line 272 on the board.
3. Press Confirm SO389394 and stay on step 1 "Review split".
4. Read the LOCATION cell of line 272.
5. Close the dialog without confirming.
6. Sidebar: Project Sales Admin > Sales Orders, open SO427856, Edit, change line 64's location from BRW-IB to the
   sibling location, keep qty and date, Save.
7. Sidebar: Supply Chain > Project Demand, filter SO427856.
8. Open the change icon on line 64.
9. Re-decide line 64 as the same Buy 20, press Confirm for the order and read step 1 "Review split" (also at 375px
   wide) before confirming.
10. Open the purchasing email that Confirm sent (Order Inquiry handover / email outbox) and its Excel attachment.
11. Open SO427856's Order Inquiry rows for line 64.
12. Put line 64 back on BRW-IB (Project Sales Admin > Sales Orders, Edit, Save) and re-confirm it on the board.

## Expected
- Step 4: LOCATION reads the same as the board at step 2 (the AutoCount location), not the planned one; no New
  location column (no pending move on SO389394).
- Line 272 does not show as changed on the board at step 2 (no backfill for moves before this ships).
- Step 8: the change lightbox shows a Location row, Was = BRW-IB, Now = the sibling location (no Qty or Date row
  moved).
- Step 9 (Review split): line 64 reads Location = BRW-IB and New location = the sibling location (right after it);
  other lines read their own Location and a blank New location. At 375px both columns show.
- Step 10: one line for SO427856 line 64: LOCATION = BRW-IB, NEW LOCATION = the sibling location, REMARK =
  `NEW LOCATION (was BRW-IB)`. Lines that did not move have a blank NEW LOCATION. The Excel attachment has the same
  LOCATION / NEW LOCATION pair right after each other. The subject reads `OI: <location> @ SO427856`. No ORDER or
  CANCEL line for it.
- Step 11: the Order Inquiry row keeps its id, qty, state and links; no new ORDER row and no cancel.
- Step 12: the move back reads LOCATION = the sibling, NEW LOCATION = BRW-IB, REMARK `NEW LOCATION (was <sibling>)`.
