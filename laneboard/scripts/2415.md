# PR 2415 hand test: Link PO popup reads only the CRM copies; every ticked line is a row (OI-PO-LINK B)

Owner, 14 Nov ~15:50 (db3 hand test round 2): several ticked lines showed only 1 row in Link PO, and the popup
lagged on open because it asked the Shared Service. This PR: the popup reads only the CRM copies (nothing is sent
until Save), and a ticked line not in AutoCount is a row of its own.
Read-only on AutoCount: no step writes to AutoCount (the db3 budget is used up). The one Save step is optional and
needs crew's OK for writes first.

## URL
crew test copy: the db3 demo stack (AutoCount TEST book db3 only), after #2350's data (rows below).

## Setup
- Sign in as a user holding "Link PO lines in AutoCount (Stock Debt, Order Inquiries)" (`projects.stock_debt.link_po`),
  the Order Inquiry view and action grants, and `projects.projects.view`.
- User Management > Settings: "AutoCount PO links (Stock Debt, Order Inquiries)" is ON.
- Rows crew left on db3: R1 = FXT-1113-SO-A line 16 (covered by PO lines), R2 = FXT-1113-SO-A line 32 (not covered),
  R3 = an Order Inquiry row whose sales order line is not in AutoCount (e.g. OI-2611-9003), and the Order Inquiry
  document OI-2611-0002 with two lines (one in AutoCount, one not).
- Keep the Shared Service request log open (or note the time) to see which calls the CRM makes.

## Steps
1. From `/` use the sidebar: Procurement > Supply Chain > Order Inquiries.
2. Tick R1, R2 and R3, open Actions, choose "Link PO... (2 of 3)", and note how long the popup takes to show its rows.
3. Read every row of the popup grid, then press Cancel.
4. In the Shared Service request log, look for calls from the CRM between step 2 and step 3.
5. Tick R3 alone, open Actions.
6. Open Order Inquiry document OI-2611-0002 (click its number), tick both lines, open the gear, choose "Link PO... (1 of 2)".
7. Read the popup rows, tick the header box, read the header box and the main button, then press Cancel.
8. Hover the PO cell of the "Not in AutoCount yet" row.
9. Open Stock Debt, open a snapshot drill for R1's product, tick R1's sales order line, Decide > "Link PO…", then Cancel.
10. Narrow the window to 375 px and repeat step 2, then Cancel.
11. (Optional, only with crew's OK for one AutoCount write) In step 2's popup, on R2's new row pick an old-book PO line (e.g. FXT-1110f-SPO1), press Save, read the card, press Done.

## Expected
2. The popup shows its rows at once (no wait on AutoCount); while it loads the menu reads "Getting the PO lines", never "Checking AutoCount…".
3. Three rows, one per ticked line: R1 (its linked PO rows with the Keep / Unlink / Change to picker under "Action"), R2 (a new row: PO picker and qty under "Qty"), and R3 as its own row reading "Not in AutoCount yet" in the PO column, with no tick box, no PO picker and no qty. There is no separate note under the grid. Every row is one line; no sideways scroll at 1280 px.
4. No call from the CRM to the Shared Service at all while the popup opened (no `write-capabilities`, nothing else).
5. "Link PO..." is greyed with "Not in AutoCount yet" (no line of the ticked rows is in AutoCount).
7. Two rows: the AutoCount line (new row, usable) and the other line as "Not in AutoCount yet". Ticking the header box ticks only the AutoCount line and shows fully ticked (not mixed); the main button counts only that line, e.g. "Save (1)" once a PO line is picked, otherwise "Save (0)".
8. A hover shows the Order Inquiry number and item code with "Not in AutoCount yet". The Sales order cell reads the sales order number when the CRM has one, otherwise "-" (never the Order Inquiry number).
9. The same popup as on Order Inquiries; it opens without a Shared Service call (check the log as in step 4).
10. The page does not scroll sideways; the popup fits (its grid scrolls inside it) and Save and Cancel are on screen.
11. One card "Not linked" / "FXT-1113-SO-A line 32: PO FXT-1110f-SPO1 was not found in AutoCount. Nothing was changed." with "Try again". The Shared Service call happens only now, at Save.
