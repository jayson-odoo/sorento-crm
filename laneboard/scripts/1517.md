# Hand test #1517 (ROGUE-CONVO-REVIEW PR-1: class A, zero-scope list + chat visibility)

## URL
crew test copy

## Setup

1. No migration: the lane adds no column. One optional data step on the shared dev DB so step 4
   has something to hide (idempotent; flags ONE internal line the chatbot must never list):
   ```sql
   -- pick one internal line and remember its code
   SELECT product_code, product_name, is_searchable, is_active FROM products
   WHERE product_code ILIKE 'AC-EXP-%' ORDER BY product_code LIMIT 3;
   UPDATE products SET is_searchable = false WHERE product_code = '<one AC-EXP code>' AND is_searchable IS DISTINCT FROM false;
   ```
   Undo later with `UPDATE products SET is_searchable = NULL WHERE product_code = '<that code>';`.
2. Sign in to the test copy and open the chatbot console. Pick a dealer contact (General Enquiries
   access is fine) with no open task or picker (send `cancel` first if one is open).
3. Note one real product code the contact may see (e.g. `SRTWC286`) and the brand list on the
   contact (Edit Contact, "Brands"): if it is scoped, note one brand it does NOT carry and a
   product of that brand.

## Steps

1. Type `product` on its own.
2. Type `price` on its own.
3. Type `<real code> price` (e.g. `SRTWC286 price`).
4. Type the category word of the flagged internal line's category (e.g. `account department
   products`), or `<the flagged AC-EXP code> price`.
5. Type `srtwc-99999 price` (a code that exists nowhere).
6. Type `PO` on its own.
7. Type `stock?` on its own.
8. If the contact is brand-scoped: type `<other-brand product code> price`.
9. Admin UI control: open Master Data > Products in the CRM and search the flagged AC-EXP code.

## Expected

1. `That would search every product we have - I need at least one filter to narrow it down. Give
   me a product code, category, or brand, and I can look it up.` No product list, no "Here are
   the matching products.".
2. The same sentence.
3. That product's price line (one product, its code, its price). The console trace shows ONE
   `crm_master_products_list` call carrying `product_ids` with that product's id and
   `chat_visible: true`.
4. The flagged line never appears in any reply (a category ask lists the category's other,
   searchable, active products; the direct code ask reads as a miss for that code, `Couldn't
   find ...`), never its name "FOR ACCOUNT DEPARTMENT ONLY".
5. `Couldn't find ...` naming `srtwc-99999` (a did-you-mean if the catalogue has neighbours); no
   product list; the trace shows NO `crm_master_products_list` call.
6. The open PO book as before (unchanged control: a bare PO ask lists).
7. `That would search every stock we have - I need at least one filter ...` (unchanged control).
8. A miss for that code (the brand bound, unchanged by this PR); no price.
9. The admin list still shows the flagged AC-EXP line (the flag hides it from the chatbot only).
