# Hand test: PR #2233 NPA-FROM-SI (New Product Application from a Stock Inquiry)

Purchasing flags "NPA needed" on its stock inquiry reply; the salesperson raises the application from the
inquiry, prefilled; purchasing answers it in the stock inquiry's own "Edit purchasing response" dialog, with
Save only or Update & Reply, and Update & Reply sends the stock inquiry's own reply.

## URL
crew test copy

## Setup
1. Apply the latest `crew-migration:` on the PR first. It adds `purchasing_response` and widens
   `new_product_applications.project_name` to TEXT.
2. Accounts (CRM unless stated):
   - Admin: holds every NPA permission; plays purchasing and the approver.
   - Salesperson A: the salesperson user linked to contact 678da08e (holds the NPA form).
3. SI-A = SI26-0191 (or SI26-0102 / SI26-0139). It needs a Respond.io conversation, as any stock inquiry
   that shows "Update & Reply".
4. SI-LONG = SI26-0139 (project name of 586 characters).
5. NEWCODE: any active code except SRTWB1633, SRTWT8207 or CB313.
6. MOCHACUST = 300-1002 "1 LIVING DEPOT SDN BHD - [CERAMIC]" (Mocha). SORCUST: a Sorento customer.

## Steps
1. As Admin, open SI-A, press "Edit purchasing response". Note the dialog: its description line, fields
   and buttons. Tick "Salesperson must create a New Product Application", type any response, press "Save only".
2. As Salesperson A, open SI-A, press "Create new product application". In CUSTOMER type "LIVING DEPOT", pick
   MOCHACUST, press "Save as draft".
3. Change CUSTOMER to SORCUST, press "Save as draft", then Submit.
4. As Admin, open the application, press Approve. Look at the header buttons.
5. Press "Edit purchasing response" on the application. Compare it with step 1's dialog.
6. Leave "Purchasing response" empty and look at the two save buttons.
7. Type "Supplier can cut 600 x 900.", choose "Link an existing product code", pick NEWCODE, set Lead time
   "8 weeks" and Cost (MYR) "210", press "Save only".
8. Look at the application, and at the requester's bell (Salesperson A).
9. Press "Edit purchasing response" again, change the text to "Code opened, please quote.", press
   "Update & Reply".
10. Open SI-A's conversation (Respond.io, or the SI's chat) and compare the message with the one an SI's own
    Update & Reply sends.
11. As Salesperson A, open SI-LONG and press "Create new product application", press "Save as draft".
12. Open the saved application.
13. Close SI-A (Admin, from SI-A's own page), then open the step 2 application and press "Edit purchasing
    response". Change the text and press "Save only".
14. Repeat steps 1, 5, 9 and 12 at 375 px wide.

## Expected
- Step 1: the SI dialog, in order: description "Save updates the record only. Update & Reply saves your text
  and sends it to the contact.", "Purchasing response" text, the NPA checkbox, Attachments, then Cancel /
  "Save only" / "Update & Reply".
- Step 2: the CUSTOMER list equals the SI's, Mocha rows included; it saves as text
  "300-1002 - 1 LIVING DEPOT SDN BHD - [CERAMIC]". No product table.
- Step 3: SORCUST links with its code. Submitted shows no "Waiting for approval / Locked" banner.
- Step 4: Revise, "Edit purchasing response" and the red-outline "Reject" (the SI's button).
- Step 5: the same dialog as the SI's, with the same description line. "Purchasing response" text first,
  then Link an existing product code / New product code, Lead time, Cost (MYR), then Cancel / "Save only" /
  "Update & Reply". No "Not opening", no "No answer yet".
- Step 6: "Save only" and "Update & Reply" are both disabled while the text is empty, as on the SI.
- Step 7: saves, the dialog closes. Nothing is sent to the conversation.
- Step 8: Completed; NEW PRODUCT CODE = NEWCODE, LEADTIME 8 weeks, COST MYR 210.00, PURCHASING RESPONSE
  "Supplier can cut 600 x 900.". The requester's bell shows "NPA-xxxxxx is done: the codes are open": this is
  the application's lifecycle notice, already on main (#1769) for EVERY completion however it happens (it fires
  because linking the code completed the application), not a reply. Save only sends no message.
- Step 9: saves; PURCHASING RESPONSE reads the new text. No new bell (the application was already Completed).
- Step 10: the SI's own reply (template stock_inquiry_update_with_button out of the 24 h window): "Stock Inquiry
  No - SI-A ... / Update: NPA-xxxxxx: Code opened, please quote. / New product code: NEWCODE / Lead time:
  8 weeks", and its View button opens the SI portal page. In the window it is the SI's text reply "There is a
  response to your stock inquiry:" with the same update lines and the portal link.
- Step 11: saves (no "String should have at most 255 characters").
- Step 12: PROJECT shows two lines, cut off, with an eye button that opens the full 586-character name.
- Step 13: like the closed SI's own dialog, the application's dialog has NO "Update & Reply" (only Cancel /
  "Save only"), and Save only still saves the text. Nothing is sent. (The API refuses a reply on a closed SI
  with the SI's own sentence, and saves nothing.)
- Step 14: both dialogs fit the phone with the same footer stacking; the clamped PROJECT stays two lines;
  nothing scrolls sideways.
