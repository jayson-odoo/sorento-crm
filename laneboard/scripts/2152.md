# Hand test: PR #2152 OI-ROUTE-BY-RAISER (order inquiry emails routed by who raised the OI)

Automation rows for the order inquiry emails can now be set by who raised the order inquiry
(condition "Raised by"). One raiser's project orders go to their own row; the general project row
skips them. Send to purchasing follows the same rows. Saving a row without touching a To/Cc
address no longer changes how it splits To and Cc. Mail does not leave a test copy, so the check
is the preview's To line, each row's run history and the notification rows.

The copy has no Eling project row and no OIs raised by Agnes, so this script uses stand-ins:
Aisyah plays Agnes (the raiser), Lin plays Agnes' team (TEAM), and a new "ZZT General project
orders" row plays Eling's row.

## URL
crew test copy

## Setup
- Signed in as an admin, one browser tab.
- Two open project order inquiries: AISYAH-OI raised by Aisyah, OTHER-OI raised by someone else
  (the browser pass used OI-2610-0097 and OI-2610-0084; check which is Aisyah's in the Raised by
  column).
- Run on the copy's DB and note the answer (call it LEGACY-ROW):
  `SELECT name, recipient_config->>'explicit_to_cc' AS explicit FROM automations WHERE trigger_type = 'order_inquiry_handover' ORDER BY created_at;`
  Pick a row whose explicit is empty or false.

## Steps
1. From `/`, open the sidebar System > Configuration > Automation.
2. Open LEGACY-ROW, click Edit, change only its Description (add " test"), Save.
3. Run the Setup query again.
4. Click Add automation. Trigger: Order inquiry handover to purchasing; the same email template as LEGACY-ROW; name "ZZT General project orders"; To: any user who is not Lin (call them GENERAL); tick One email, everyone on the thread.
5. Add condition Sales order class, is, Project. Add condition Raised by, is none of, Aisyah. Enabled on. Save.
6. Click Add automation. Same trigger and template; name "ZZT Aisyah project orders"; To: Lin; tick One email, everyone on the thread.
7. Add condition Sales order class, is, Project. Add condition Raised by, is any of, Aisyah. Enabled on. Save.
8. Switch every other enabled handover row off (Edit, untick Enabled, Save) and note which ones, so only the two ZZT rows are enabled.
9. From `/`, open the sidebar Procurement > Supply Chain > Order Inquiries and open AISYAH-OI.
10. Open the gear menu (Order inquiry options), click Send to purchasing. Read the preview, then Cancel.
11. Go back, open OTHER-OI, gear menu, Send to purchasing. Read the preview, then Cancel.
12. Open AISYAH-OI again, gear menu, Send to purchasing, then Send.
13. Open System > Configuration > Automation > "ZZT Aisyah project orders" and read its run history; then open "ZZT General project orders" and read its run history.
14. Run on the copy's DB: `SELECT title, data->'recipient_emails' AS recipients, data->>'to_count' AS to_count, created_at FROM notifications WHERE type = 'automation_email' ORDER BY created_at DESC LIMIT 2;`
15. Switch the rows from step 8 back on.

## Expected
- Step 3: LEGACY-ROW's explicit is still empty or false (a save that changed no To/Cc address keeps first-To-rest-Cc).
- Step 5: the row detail reads "Sales order class is Project AND Raised by is none of Aisyah" (a name, never an id).
- Step 7: the row detail reads "Sales order class is Project AND Raised by is any of Aisyah".
- Step 10: exactly one email in the preview; its To is Lin; GENERAL is not on To or Cc; the line ticks show.
- Step 11: exactly one email; its To is GENERAL; Lin is not on it.
- Step 12: the dialog closes with a success message and no skipped order inquiry.
- Step 13: "ZZT Aisyah project orders" has one new run (Mode manual, Attempted 1 or more); "ZZT General project orders" has none from step 12.
- Step 14: the newest row's title ends "(Resent)"; recipients is Lin's address only (to_count 1); GENERAL's address is not in it.
