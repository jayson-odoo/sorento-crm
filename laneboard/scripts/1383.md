crew test copy, build 7bbf2f80 (the branch head above it adds only this file; fake FoundryX on :8009 fed by `scripts/build_fake_foundryx_data.py --do-from/--do-to`; crew fills the local URL here)

## Setup

1. The pull permission on the shared dev DB (the PR's crew-migration SQL); log in as a user holding `order_management.orders.autocount_pull` (admin has it after the SQL).
2. Worker running on the `imports` queue (the preview and the apply are RQ jobs). If the copy is restarted while a preview runs, the pull stays "Preparing": click Discard on it and pull again (the scheduler's orphan sweep does this on its own on prod, see the PR note).
3. FoundryX: the branch's fake fed with the dev copy's OWN delivery orders, so every pulled DO already exists and the pull adopts it by number. From `sorento_crm_backend/` of the test copy:
   `venv/bin/python scripts/build_fake_foundryx_data.py --database-url <the test copy's DATABASE_URL> --company-code SRT --do-from 2026-09-01 --do-to 2026-09-30 --out /tmp/fake-foundryx-data`
   then
   `FAKE_FOUNDRYX_DATA=/tmp/fake-foundryx-data FAKE_FOUNDRYX_BUILD_SECONDS=10 venv/bin/python -m uvicorn tests.support.fake_foundryx:app --port 8009`
   The builder prints "delivery_orders: N documents, L lines" (crew's smoke run: N = 4,412, L = 12,444).
4. System Management > Integrations > foundryx-esb: Base URL `http://localhost:8009`, any key, Test shows Connected.
5. Have the Order Listing macro's Master sheet for September 2026 to hand (Doc No, Item Code, Location, Qty columns) for step 10.

## Steps

1. Sidebar: Dashboards > Delivery Orders.
2. Open the Actions menu; it lists Refresh, Import tracking, Import delivery order lines, Pull from AutoCount.
3. Click Pull from AutoCount; a dialog "Pull delivery orders from AutoCount" opens. Read the two dates, then click Pull.
4. You land on the pull page (Import Jobs > AutoCount Delivery Orders Pull); the pill reads Building.
5. Wait; the pill reads Preparing with "x of N", then Awaiting confirm.
6. Read the header line and the counters row.
7. Open the Changes tab; read the first rows.
8. Open the Excel view tab; type one DO number from the list into the search box.
9. Click Download xlsx and open the file.
10. Open Compare with my Excel; drop the Order Listing macro (.xlsm) on the left dropzone, then the Order Tracking macro (.xlsm) on the right one.
11. Click Back to Delivery Orders; open the Actions menu again.
12. Click Review pull.
13. Click Confirm.
14. Click View apply job.
15. Go to Delivery Orders, open one of the pulled DOs (a delivered one with a transporter), read its tracking fields.
16. Delivery Orders > Actions > Pull from AutoCount again; wait for Awaiting confirm; read the counters.

## Expected

1. The Delivery Orders list opens.
2. Four actions; the last one reads exactly "Pull from AutoCount" (it is absent for a user without the permission).
3. The dialog shows From day / To day prefilled with the last 31 days (today and the 30 days before it), no other field; Pull closes it and the page navigates.
4. Pill "Building"; page title "AutoCount Delivery Orders Pull"; Back button reads "Back to Delivery Orders".
5. "Preparing" shows "x of N" with N = the builder's document count; "Awaiting confirm" within a few minutes (4,412 documents preview in about 2 to 3 minutes).
6. Header: "AutoCount delivery orders pull, SRT", "Snapshot dd/mm/yyyy hh:mm, valid until ...", "Scope: dd/mm/yyyy to dd/mm/yyyy" (the two days from the dialog). Counters: Received N, New 0, Updated 0, Adopted by number N, Unchanged 0, Lines to delete 0, Failed 0, Retry later 0, With warnings = the number of DOs whose debtor code is not a customer (may be 0).
7. One row per DO, outcome Updated, message "DO adopted by number: <DocNo>: tracking kept, k line(s) kept, 0 created, 0 deleted" (k = that DO's line count); warnings, when any, read in words at the end ("warnings: customer not found").
8. L rows in total (one per DO line) with columns Doc No, Doc Date, Debtor Code, Debtor Name, Item Code, Description, Location, Qty, UOM, Unit Price, Sub Total; the search leaves only that DO's lines.
9. File `autocount-delivery_orders-pull.xlsx`, header row exactly those eleven columns, L data rows.
10. Two dropzones ("Order Listing (macro), sheet Master" and "Order Tracking (macro), sheet Master") and a line "Compared inside the pulled window only, dd/mm/yyyy to dd/mm/yyyy ...". After each drop a line under it reads "N lines/documents in the window, M outside it ignored". One headline "x of y match" over both files; one grid with columns Doc No, Item Code, Location, Difference, Your Excel, AutoCount pull, Source (Lines / Headers). With the fake data every September line the sheet shares with the CRM matches; lines or DOs the CRM never had show "Only in your Excel". Confirm stays enabled (advisory; the switch AUTOCOUNT_DO_PULL_CONFIRM_REQUIRES_MATCH is off).
11. The Actions menu's last item now reads "Review pull".
12. The same pull page opens (same URL).
13. Toast "Confirmed. Applying now."; pill "Confirmed"; a "View apply job" button appears.
14. Apply job finished; N rows with outcome Updated; no Failed rows.
15. Transporter, driver, lorry plate, actual delivery date, remarks CS are unchanged.
16. A new pull; counters: Received N, Unchanged N, everything else 0 (a second pull of the same snapshot changes nothing).
