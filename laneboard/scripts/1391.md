# Hand test #1391 (CHATBOT-EMPTY-ROUTE-PICK)

## URL
crew test copy

## Setup

1. Open the Chatbot Console on the test copy (Chatbot > Console) as an admin. Never test this through WhatsApp.
2. Pick the contact CONTACT Z (the 30 Sep repro contact), or any contact scoped to Sorento that may ask about orders.
3. Run the steps twice: once on the production prompt (v41 "picker fix", the label on prod since 30 Sep 03:54Z) and once with the console's prompt override set to v37 "spec and reverse asking" (the version the 30 Sep repro ran on; it already carries the open-question rule, so the phantom pick was model behaviour and the code guard is what must hold). Do not use v40 for either run: it is a plain-lineage version with no policy blocks and is never to be promoted.
4. Press Reset on the console so no question is open before each run.

## Steps

1. Send "DO for cheng huat sentul" (or any customer with delivery orders) and wait for the list.
2. Send "Zhin heng delivered on 23/9".
3. Open the turn's trace (Turn detail) and read the Parse section: raw vs post-processed, and the events list.
4. If step 2 asked "Which customer do you mean? Please choose:", reply "1".
5. Press Reset. Send "Zhin heng delivered on 23/9" as the first message of a fresh conversation.
6. Press Reset. Send "DO for cheng huat sentul", wait for the list, then send "what about 2019".

## Expected

1. The DO list for the customer, as before.
2. Either "Which customer do you mean? Please choose:" followed by the numbered Zhin Heng families, or, if the name resolves to one account, the data answer. In no case does the reply contain "Please choose who to route to (reply with the number):" or "If you have no preference, just reply 'yes' and we'll assign automatically.", and no blank line stands between the "Customer: ..." header and the next line.
3. Post-processed `open_question_answer` reads `{"mode": null, "picked": [], "items": [], "qty_for_all": null}` and `reference_positions` reads `[]` whatever the raw output says; when the raw output carried a pick, the events list has a `phantom_answer` entry naming it.
4. The delivered orders list for the picked family, on both prompt versions.
5. A normal first ask: the customer picker when the name is ambiguous, else "Here's what you want ..." with "But no order matched these. Would you like me to escalate to *Sorento* customer service team?" and, when customer service members are configured, "Please choose who to route to (reply with the number):" with at least one numbered name under it. Never the header over an empty list.
6. The list header line(s) and "No orders matched these." as the last line. No escalate offer, no "Please choose who to route to", no "reply 'yes'", no blank line in between.
