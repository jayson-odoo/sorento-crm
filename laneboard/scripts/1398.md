# Hand test #1398 (STOCK-DEBT-LENDABLE)

## URL
crew test copy

## Setup

1. Sign in as a user who can open Supply Chain > Project Demand > Stock Debt and who can press Confirm on Fulfilment Planning (holds `projects.projects.edit`).
2. Shared dev DB, product SRTSS8710, book Project. Before the change: SO381065 (due 29/03/2027) reads Pinned 88 "On hand BRW-BB"; SO396071 (due 01/09/2026) reads Short 32; Sep 26 cell -76, Oct -29, Dec -207.
3. Note SRTSS8710's lead time (Product > Suppliers, standard lead time; 90 days when none is stated). SO381065's due date must be on or after today + lead + 14 days for the lend to apply; on 30 Sep 2026 with a 90-day lead that is 12 Jan 2027, so 29/03/2027 qualifies.
4. Know the current count of ORDER_BACK order inquiry rows for SO381065 (step 9's query, run once before).

## Steps

1. From the sidebar open Supply Chain > Project Demand > Stock Debt, set Book to Project, search `SRTSS8710`.
2. Read the Sep 26, Oct 26, Dec 26 and Mar 27 cells of the row.
3. Click the Sep 26 cell. Read SO396071's row on the Demand tab (Status, Assigned, Covered by).
4. Close it. Click the Mar 27 cell. Read SO381065's row (Status, Assigned, Covered by).
5. Set Due to (date range end) to 31/12/2026. Read the Sep 26 cell and SO396071's row again. Clear the date.
6. In the Mar 27 cell dialog press Rebalance. Read the Preview.
7. Press Confirm N orders. Read the result block and the refreshed rows.
8. From the sidebar open Supply Chain > Project Demand > Order Inquiries; search SO381065.
9. Read-only check, run against the shared dev DB (replace nothing):

```sql
SELECT r.verb, r.qty, r.delivery_date, r.state, r.note
FROM projects.order_inquiry_rows r
JOIN projects.sales_order_lines l ON l.id = r.so_line_id
JOIN projects.sales_orders p ON p.id = l.project_sales_order_id
JOIN sales_orders so ON so.id = p.so_id
WHERE so.so_number = 'SO381065' AND r.verb = 'ORDER_BACK'
ORDER BY r.created_at DESC;
```

   Or the API: `GET /api/v1/project-sales/stock-debt/<SRTSS8710 product id>/rebalance` before step 7 lists the transfers; after step 7 it answers `orders: []` for the lends that were confirmed.

## Expected

2. Sep 26 improves by the lent quantity: -76 becomes -44 (32 lent to SO396071). Oct 26 improves by up to 29, Dec 26 by whatever of the 88 is left, and Mar 27 reads the lent total as a negative amber cell (for example -88 when all 88 went out). Exact figures depend on which nearer BRW-BB lines are short on the day.
3. SO396071: Status `covered`, Assigned 32, Covered by `On hand BRW-BB (from SO381065)`.
4. SO381065: Status `order back N` (violet pill) where N is the lent total; Assigned = 88 - N; Covered by lists `Lent to SO396071 (32)` and the other receivers with their quantities. If N is 88 the Assigned column reads 0.
5. Sep 26 reads the same -44 and SO396071 the same `covered` 32 with the date range set (the lender's row is hidden by the range, so Covered by reads `On hand BRW-BB` without the name). Nothing else moves.
6. Preview lists one block per receiving sales order that is adopted on fulfilment planning: `Borrow 32 on hand at BRW-BB from SO381065 line <n> (<agent>, due 29 Mar 2027); its debt lands in Mar 2027`, an `Order back 32 for SO381065 at 29/03/2027` line, and for a partly lent line a `Buy <rest>` line. A receiving order not yet adopted is listed under "Not previewed" with the reason. The Rebalance button is greyed while the Preview is open.
7. Result block names each order with its revision number; a refused order shows the server's reason and the others still land. SO396071's row now reads `pinned` with Covered by `On hand BRW-BB`. SO381065 no longer lists `Lent to SO396071`.
8. The worklist shows an Order back row for SO381065, qty 32, delivery date 29/03/2027, note `Order-back: SO381065 line <n> lent 32 to SO396071 line <m>`.
9. The query returns one new ORDER_BACK row per confirmed receiver, `qty` = the lent quantity, `delivery_date` = 2027-03-29, state `raised` (or `placed` if the auto-link found a document for it).
