# PR 2361 hand test: Last activity column, sortable, on every form list

## URL
crew test copy

## Setup
- Apply the `crew-migration:` SQL from the PR (adds `last_activity_at` to the seven form tables, fills it from existing History, and lets sample requests take comments). Safe to run twice.
- Sign in as admin.
- Any purchase request that is NOT at the top of the Purchase Requests list, and any stock inquiry.

## Steps
1. From `/`, open Project Sales Admin > Purchase Requests in the sidebar.
2. Look at the Last activity column and the order of the rows.
3. Open the purchase request from Setup (one that is not at the top) and post a comment on its Comments tab.
4. Go back to the Purchase Requests list.
5. Click the Last activity header four times, looking at the first row and the header arrow after each click.
6. Open Filters, set Last activity to today's date for both ends, apply.
7. Open the first row, then press next (the pager in the record header) until the end.
8. Go back to the list, remove the Last activity filter chip.
9. Open Columns, hide Last activity, then show it again; reload the page.
10. Open Procurement > Stock Inquiries; look at the Last activity column, then click its header twice.
11. Open, in turn from the sidebar: Complaints > Complaints, Project Sales Admin > Sponsorship Forms, Dealer Kit > Price Tag Requests, Project Sales > Sample Requests, Procurement > New Product Applications; then the workflow form submissions list (it has no sidebar entry: open it from Workflow Forms).
12. Shrink the browser to phone width (375px) on Purchase Requests.

## Expected
- Step 2: the column header reads "Last activity"; each value reads like `12/11/2026, 9:45 am` on one line with no "..." at normal width; the list is newest first (the Last activity header shows the down arrow).
- Step 4: the purchase request you commented on is now the first row, with today's date and the time of your comment.
- Step 5: click 1 newest first, click 2 oldest first (up arrow), click 3 newest first (down arrow), click 4 no arrow and still newest first (never oldest first without an arrow). In each order, page 2 continues it.
- Known: a user who saved a column layout on Stock Inquiries before this change keeps the old, narrower width there (the time may show "..." with the full value on hover) until they reset Columns.
- Step 6: only records with activity today remain, including the one from step 3; a "Last activity" chip shows the range `dd/mm/yyyy - dd/mm/yyyy`.
- Step 7: next walks only the filtered records, in the list's order.
- Step 8: all records come back, newest first.
- Step 9: Last activity disappears and comes back; after the reload your choice is kept.
- Step 10: values have no "Revised" word in front of them; the header click sorts (the first row changes).
- Step 11: every list shows a Last activity column, newest first by default. On Workflow Forms > Submissions the old "Updated" column is now "Last activity".
- Step 12: the page does not scroll sideways; the table scrolls inside its box and Last activity stays on one line.
- A background job (SLA timer, ERP sync) never moves a record to the top; only a person's action (edit, status change, approval, line change, attachment, comment) does.
